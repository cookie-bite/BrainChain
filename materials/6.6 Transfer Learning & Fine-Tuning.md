# Transfer Learning & Fine-Tuning

## Introduction

Last week you trained CNNs from scratch on small datasets and saw, painfully, how easy it is for them to overfit. Even with dropout, batch normalisation, and aggressive augmentation, a from-scratch CNN on a few thousand images will rarely match the performance of a model that has seen millions of images during training.

What if you could borrow the visual representations a giant model learned on ImageNet — its sense of edges, textures, shapes, objects — and reuse them for your specific problem? That's the core idea of transfer learning, and it is, without exaggeration, the single most important practical technique in modern deep learning. It's what makes deep learning usable for problems where you don't have a million labelled examples.

In this lesson:

* Layer freezing: which weights to update and which to leave alone

## Why Transfer Learning Works

A deep CNN trained on ImageNet (1.2 million labelled images, 1 000 classes) learns a hierarchy of visual features. Looking at activations across layers reveals a striking pattern:

* **Early layers** detect generic, low-level features: edges, gradients, simple textures, blobs of colour.
* **Middle layers** detect parts and motifs: eyes, wheels, leaves, fur patterns.
* **Late layers** detect specific concepts: full objects, scenes, breeds.

Here's the key insight: early- and middle-layer features are useful for almost any image task. Edges and textures are not specific to ImageNet's cat-vs-dog distinction; they're useful for detecting Mars rovers, satellite imagery defects, medical scans, and yes, your cat photos.

So instead of relearning "what an edge looks like" from scratch on your 3 000-image dataset, you start with weights that already know — and you only train (or fine-tune) what's specific to your problem.

The same principle applies to NLP, where models like BERT and GPT trained on hundreds of billions of tokens learn linguistic structure (syntax, semantics, common-sense relationships) that transfers to almost any text task.

## Two Modes: Feature Extraction vs Fine-Tuning

There are two ways to use a pretrained model. Choose based on dataset size, task similarity, and compute budget.

### Mode 1: Feature Extraction (Frozen Backbone)

Treat the pretrained model as a fixed feature computer. Strip off its original classification head, replace it with a small new head, and train only the new head on your data.

```
   ┌────────────────────┐    ┌────────────────────┐
   │  Pretrained        │    │  New classifier    │
   │  backbone          │ ─► │  head              │
   │  (FROZEN)          │    │  (TRAINABLE)       │
   └────────────────────┘    └────────────────────┘

```

No gradients flow through the backbone — only the small classifier head learns from your data.

* **What you train:** the new head (typically a few thousand parameters).
* **What stays fixed:** the backbone (typically tens of millions of parameters).

**When to use:**

* Your dataset is small (~hundreds to a few thousand examples)
* Your task is similar to the pretraining task
* You want the fastest training and the lowest risk of overfitting
* Compute is limited

In PyTorch:


```
from torchvision import models
backbone = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)

for p in backbone.parameters():
    p.requires_grad = False                # freeze everything

# Replace the final classifier (last fully connected layer)
backbone.fc = nn.Linear(backbone.fc.in_features, n_classes)  # only this trains
```

Note that backbone.fc.requires_grad is True by default for the new layer because we just created it — only the previously frozen layers stay frozen.

### Mode 2: Fine-Tuning (Unfreeze Some or All Layers)

Start from pretrained weights, but allow them to be updated during training. Usually you start by training only the new head (the feature-extraction phase), then unfreeze later layers and continue training with a much smaller learning rate.

```
   ┌────────────────────┐    ┌────────────────────┐
   │  Pretrained        │    │  New head          │
   │  backbone          │    │                    │
   │  (trainable,       │ ─► │  (trainable,       │
   │   low LR)          │    │   normal LR)       │
   └────────────────────┘    └────────────────────┘

```

Both parts update, but the backbone uses a much smaller learning rate (typically ~10× smaller) so it doesn't forget the general features it already learned.

**When to use:**

* Your dataset is medium-sized (a few thousand to tens of thousands of examples)
* Your task differs from the pretraining task in non-trivial ways
* You have time and compute for a longer training run

The key trick: use a much smaller learning rate for the pretrained layers (e.g., $1e-5$) than for the new head (e.g., $1e-3$). The pretrained weights are already in a good neighbourhood — you want to nudge them, not throw them.


```
optimizer = torch.optim.Adam([
    {"params": backbone.layer4.parameters(), "lr": 1e-5},
    {"params": backbone.fc.parameters(),    "lr": 1e-3},
])
```

This pattern of discriminative learning rates is one of the most important tricks in transfer learning.

## A Decision Table

| Dataset size | Task similarity | Recommended mode |
| --- | --- | --- |
| Very small (<1 000) | Similar to pretraining | Feature extraction |
| Small (1 000–10 000) | Similar | Feature extraction first; consider fine-tuning the last block |
| Medium (10 000–100 000) | Similar | Fine-tune the last few blocks |
| Medium | Different | Fine-tune more blocks (or all) |
| Large (>100 000) | Different | Fine-tune the entire network with low LR |

For Friday's cat-detection assessment, you'll be improving a YOLO26 detector you already trained in Week 1 — so the pretrained backbone is a YOLO26 variant pretrained on COCO (animals plus 79 other classes). The dataset is "small to medium" and "similar" to pretraining, which puts you firmly in the "fine-tune the last few blocks" quadrant. The Ultralytics API hides the layer-freezing mechanics behind sensible defaults; what you tune in practice is the size of the backbone, the learning rate, and the augmentation recipe.

## Freezing Layers in Practice

In PyTorch you control which parameters are trainable via the requires_grad flag:


```
# Freeze everything
for p in model.parameters():
    p.requires_grad = False

# Unfreeze just the last block
for p in model.layer4.parameters():
    p.requires_grad = True

# Always also unfreeze the new head (not strictly necessary if you replaced it,
# but explicit is better than implicit)
for p in model.fc.parameters():
    p.requires_grad = True
```

A common pattern is gradual unfreezing: start with everything frozen except the new head, train for a few epochs, then progressively unfreeze deeper layers and continue training with smaller learning rates each time. fast.ai popularised this; modern toolkits make it a one-liner.

## What About BatchNorm?

Special care is needed for BatchNorm layers when fine-tuning small datasets. By default, BatchNorm computes statistics from the current mini-batch, which can be unstable on small batches and can drift far from the pretrained statistics. Two common fixes:

1. Set BatchNorm layers to model.eval() mode while you train, so they use the pretrained running statistics:


```
def freeze_bn(module):
    if isinstance(module, nn.BatchNorm2d):
        module.eval()
        for p in module.parameters():
            p.requires_grad = False
model.apply(freeze_bn)
```

2. Or simply use a larger batch size (which is sometimes not feasible).

This is the kind of detail that separates a good fine-tuning result from a great one. Worth being aware of when your fine-tuned model performs worse than feature extraction — BatchNorm chaos is often the culprit.

## A Practical Recipe (Vision)

Here's a recipe that works for most image classification problems with limited data:

1. Load a strong pretrained backbone: torchvision.models.resnet50(weights="DEFAULT") (or EfficientNet, ConvNeXt, etc.)
2. Replace the final classifier: model.fc = nn.Linear(model.fc.in_features, n_classes)
3. **Stage 1 — feature extraction:**
* Freeze the entire backbone.
* Train only the new head with Adam(lr=1e-3) for ~5 epochs.


4. **Stage 2 — fine-tuning (optional but often helpful):**
* Unfreeze the last block (layer4 for ResNet).
* Use a small learning rate ($1e-4$ or $1e-5$).
* Train for another 5–10 epochs.


5. Watch validation loss closely — fine-tuning is fast to overfit. Use early stopping.
6. **Augmentation** — keep using the same training-time augmentation as a from-scratch model. Pretrained features are robust but augmentation still helps.

## Transfer Learning in NLP

Transfer learning isn't just for images. It's the only way modern NLP works.

The pattern:

1. **Pretraining** — train a transformer (BERT, RoBERTa, GPT, T5, …) on enormous unlabelled text corpora using a self-supervised objective like masked language modelling or next-token prediction.
2. **Downstream task** — take the pretrained model and either fine-tune it on a small labelled dataset for your task, or just use it as a feature extractor (encoder-only models often produce great sentence embeddings out of the box).

A typical NLP fine-tuning run, conceptually:


```
from transformers import AutoModelForSequenceClassification, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModelForSequenceClassification.from_pretrained("bert-base-uncased", num_labels=2)

# train as usual on your sentiment / classification / NER dataset
```

The Hugging Face transformers library provides hundreds of pretrained models with consistent APIs. The fine-tuning recipes are essentially the same as for vision: replace the head, optionally freeze parts of the backbone, train with a small learning rate.

This pattern is exactly what Unit 8 will explore in depth for Large Language Models.

## When Transfer Learning Doesn't Work

Transfer learning is powerful but not magic. Be careful when:

* **The domain is very different from pretraining** — medical imaging, satellite data, microscopy: pretrained ImageNet features can still help, but improvements are smaller and you may need to fine-tune deeper.
* **The input modalities differ** — pretrained image models won't help with audio waveforms unless you adapt the input (e.g., spectrograms). Pretrained text models won't help with code unless you fine-tune on code.
* **The new dataset is enormous** — at the scale of ImageNet itself, the marginal benefit of starting from pretrained weights gets small. Big enough datasets train fine from scratch.

A useful sanity check: if feature extraction (frozen backbone) does almost nothing better than chance, you're probably in a domain mismatch. Time to fine-tune deeper or pick a better starting model.

## Transfer Learning in Object Detection

When you fine-tuned YOLO26 in the Week-1 assessment, you were already doing transfer learning — the COCO-pretrained backbone gave you a head start on detecting cats. That backbone is, again, a stack of conv blocks that already knows what edges, textures, eyes, fur, and animal shapes look like. Fine-tuning teaches it to specialise.

Two transfer-learning recipes that work especially well for detectors:

1. **Quick start, small dataset** — start from yolo26n.pt and train end-to-end with a small learning rate; Ultralytics applies sensible defaults (BatchNorm stays in train mode, the head is reinitialised for your number of classes).
2. **More data, more time** — try a larger backbone (yolo26s.pt, yolo26m.pt), turn on stronger augmentation (mosaic, mixup, copy-paste), and let it train longer. This is the recipe you'll apply to improve your cat detector in tomorrow's lab and Friday's final assessment.

## Bridge to Unit 8 — LLMs

Everything you learned today applies directly to large language models. When you "fine-tune ChatGPT on your company's documents", what's really happening is exactly the recipe from this lesson — just with bigger backbones and longer training. Modern LLM techniques add a few more layers on top:

* **Parameter-efficient fine-tuning (PEFT)** — methods like LoRA and adapters that update only a tiny fraction of the parameters.
* **Instruction tuning** — fine-tune on instruction/response pairs to make the model follow user prompts.
* **RLHF (Reinforcement Learning from Human Feedback)** — use human preferences to align the model.

But underneath all of that is the same core idea: a pretrained model is a starting point, not an endpoint.

## Summary

Transfer learning is the most important practical lesson in deep learning:

* A pretrained model is a library of learned features. The first few layers are generic enough to reuse for almost any task in the same modality.
* **Feature extraction** keeps the backbone frozen and trains only a new head — best for small datasets and fast experimentation.
* **Fine-tuning** unfreezes some or all of the backbone and trains it with a small learning rate — better for medium datasets and tasks that differ from pretraining.
* **Discriminative learning rates** (different LRs for different layers) are the single most important fine-tuning trick.
* Watch out for BatchNorm when fine-tuning on small datasets; freezing it often improves results.
* Modern NLP and computer vision both run on transfer learning; the same recipe appears across modalities.
* The bridge to LLMs (Unit 8) is direct — what you'll learn there is the same idea applied at much larger scale, with a few extra tricks like LoRA and RLHF.
