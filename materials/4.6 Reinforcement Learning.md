# Reinforcement Learning

## Introduction

Imagine teaching a dog a new trick. You don't show it a dataset of correct actions — instead, you give it a treat when it does something right and withhold the treat when it doesn't. Over time, the dog figures out which behaviors lead to rewards. That's the essence of reinforcement learning (RL).

Reinforcement learning is a fundamentally different paradigm from both supervised and unsupervised learning. Instead of learning from a fixed dataset, an agent learns by interacting with an environment, taking actions, and receiving rewards. The goal is to learn a strategy (called a policy) that maximizes cumulative reward over time.

RL powers some of the most impressive AI achievements: game-playing agents that beat world champions, robots that learn to walk, recommendation systems that adapt to user behavior, and autonomous vehicles that navigate complex environments.

In this lesson, you'll learn:

* The core components of the RL framework
* How Markov Decision Processes formalize RL problems
* Key algorithms: Q-Learning, SARSA, and Monte Carlo methods
* Exploration strategies and the exploration-exploitation dilemma

We'll use the Gymnasium library (the maintained fork of OpenAI Gym) with simple environments like FrozenLake and Taxi to see these concepts in action.

> **Note:** This lesson covers classical (non-deep-learning) RL methods. Deep RL approaches like DQN and PPO will be covered in the Deep Learning unit.

## The RL Framework

Let's start by defining the key components that make up every RL problem:

* **Agent** — the learner/decision-maker (your algorithm)
* **Environment** — the world the agent interacts with
* **State ($s$)** — a description of the current situation
* **Action ($a$)** — a choice the agent makes
* **Reward ($r$)** — a numerical signal telling the agent how good its action was
* **Episode** — one complete run from start to a terminal state

At each time step, the agent observes the current state, takes an action, receives a reward, and transitions to a new state. This loop continues until the episode ends.

Let's set up a simple Gymnasium environment to see this in practice:


```
import gymnasium as gym

env = gym.make("FrozenLake-v1", is_slippery=False, render_mode="ansi")
state, info = env.reset()

print(f"Initial state: {state}")
print(env.render())
print(f"Action space: {env.action_space}")  # Discrete(4): left, down, right, up
print(f"State space: {env.observation_space}")  # Discrete(16): 4x4 grid
```

In FrozenLake, the agent navigates a 4×4 frozen grid. It starts at the top-left, needs to reach the goal at the bottom-right, and must avoid holes. The states are grid positions (0–15), and the actions are the four directions.

## Markov Decision Processes (MDPs)

The mathematical framework behind RL is the Markov Decision Process. An MDP formalizes the idea that the future depends only on the current state, not on how you got there (the Markov property).

An MDP is defined by five elements:

* $S$ — a set of states
* $A$ — a set of actions
* $P(s' \mid s, a)$ — transition probabilities: the probability of reaching state $s'$ when taking action $a$ in state $s$
* $R(s, a, s')$ — the reward function: the reward received for transitioning from $s$ to $s'$ via action $a$
* $\gamma$ — the discount factor ($0 \le \gamma \le 1$): how much future rewards are worth compared to immediate ones

The discount factor is crucial. Setting $\gamma = 0$ makes the agent myopic — it only cares about immediate rewards. Setting $\gamma$ close to 1 makes it far-sighted — it values future rewards almost as much as current ones. A typical value is $\gamma = 0.99$.

### Why the Markov Property Matters

The Markov property says: *"Given the present, the future is independent of the past."* In other words, the current state contains all the information needed to make optimal decisions. You don't need to remember the entire history.

This is a simplifying assumption, and it doesn't always hold perfectly in the real world. But it makes the math tractable and works well enough for many problems.

## Value Functions

The agent's goal is to maximize cumulative discounted reward (called the **return**):

$$G_t = r_{t+1} + \gamma \cdot r_{t+2} + \gamma^2 \cdot r_{t+3} + \dots$$

To figure out which actions are good, we need to evaluate states and state-action pairs. That's where value functions come in.

### State-Value Function $V(s)$

The state-value function $V(s)$ tells you how good it is to be in state $s$, assuming you follow a particular policy $\pi$:

$$V^\pi(s) = \text{Expected return starting from state } s, \text{ following policy } \pi$$

A high $V(s)$ means the state is "valuable" — you can expect high cumulative reward from there.

### Action-Value Function $Q(s, a)$

The action-value function $Q(s, a)$ tells you how good it is to take action $a$ in state $s$, then follow policy $\pi$:

$$Q^\pi(s, a) = \text{Expected return starting from state } s, \text{ taking action } a, \text{ then following policy } \pi$$

Q-values are especially useful because they directly tell you which action to take — just pick the action with the highest Q-value!

### Bellman Equations

The Bellman equation is the fundamental recursive relationship that connects a value function to the values of successor states. Intuitively, it says: *"The value of a state equals the immediate reward plus the discounted value of the next state."*

For the state-value function:

$$V(s) = R(s, a) + \gamma \cdot V(s')$$

For the action-value function:

$$Q(s, a) = R(s, a) + \gamma \cdot \max_{a'} Q(s', a')$$

This recursive structure is what makes dynamic programming and RL algorithms possible — you can iteratively improve value estimates by bootstrapping from neighboring states.

### Policies

A policy $\pi$ maps states to actions — it's the agent's strategy. There are two types:

* **Deterministic policy:** $\pi(s) = a$ — always takes the same action in a given state
* **Stochastic policy:** $\pi(a \mid s) = \text{probability of taking action } a \text{ in state } s$ — introduces randomness

The optimal policy $\pi^*$ is the one that maximizes expected cumulative reward from every state. Finding this optimal policy is the central goal of RL.

## Exploration vs. Exploitation

One of the most fundamental dilemmas in RL: should the agent exploit what it already knows (take the best-known action) or explore new actions that might lead to even better rewards?

Too much exploitation $\rightarrow$ the agent gets stuck in suboptimal behavior, never discovering better strategies. Too much exploration $\rightarrow$ the agent wastes time trying random actions instead of using what it's learned.

### Epsilon-Greedy

The simplest and most common strategy. With probability $\epsilon$, take a random action (explore); with probability $1-\epsilon$, take the best-known action (exploit):


```
import numpy as np

def epsilon_greedy(q_values, state, epsilon):
    if np.random.random() < epsilon:
        return np.random.randint(len(q_values[state]))
    else:
        return np.argmax(q_values[state])
```

A common pattern is to start with a high $\epsilon$ (lots of exploration) and decay it over time as the agent learns:


```
epsilon = 1.0
epsilon_min = 0.01
epsilon_decay = 0.995

for episode in range(num_episodes):
    # ... learning happens here ...
    epsilon = max(epsilon_min, epsilon * epsilon_decay)
```

### Softmax Exploration

Instead of binary explore/exploit, softmax assigns a probability to each action based on its Q-value. Higher Q-values get higher probabilities, but lower-valued actions still have a chance:


```
def softmax_action(q_values, state, temperature=1.0):
    exp_q = np.exp(q_values[state] / temperature)
    probs = exp_q / exp_q.sum()
    return np.random.choice(len(probs), p=probs)
```

The temperature parameter controls exploration: high temperature $\rightarrow$ nearly uniform (more exploration), low temperature $\rightarrow$ nearly greedy (more exploitation).

### Upper Confidence Bound (UCB)

UCB adds a bonus to less-explored actions, encouraging the agent to try them. The bonus decreases as an action is tried more:


```
def ucb_action(q_values, state, action_counts, total_steps, c=2.0):
    ucb_values = q_values[state] + c * np.sqrt(
        np.log(total_steps + 1) / (action_counts[state] + 1e-8)
    )
    return np.argmax(ucb_values)
```

UCB is principled and avoids the arbitrariness of $\epsilon$, but it's more complex and assumes non-stationary problems.

Now that you understand the core concepts, let's dive into the actual learning algorithms.

## Q-Learning

Q-Learning is one of the most important RL algorithms. It's an off-policy method, meaning it learns the optimal Q-values regardless of the policy the agent actually follows during exploration.

The Q-Learning update rule:

$$Q(s, a) \leftarrow Q(s, a) + \alpha \cdot \left[r + \gamma \cdot \max_{a'} Q(s', a') - Q(s, a)\right]$$

Where:

* $\alpha$ is the learning rate (how fast the agent updates)
* $r$ is the reward received
* $\gamma$ is the discount factor
* $\max_{a'} Q(s', a')$ is the maximum Q-value in the next state (the "greedy" part)

The key distinction: Q-Learning always uses the maximum Q-value of the next state for updates, even if the agent didn't actually take that best action. This is why it's "off-policy."

Let's implement Q-Learning on the Taxi environment:


```
import gymnasium as gym
import numpy as np

env = gym.make("Taxi-v3")

n_states = env.observation_space.n
n_actions = env.action_space.n
q_table = np.zeros((n_states, n_actions))

alpha = 0.1
gamma = 0.99
epsilon = 1.0
epsilon_min = 0.01
epsilon_decay = 0.995
num_episodes = 5000

rewards_per_episode = []

for episode in range(num_episodes):
    state, _ = env.reset()
    total_reward = 0
    done = False

    while not done:
        if np.random.random() < epsilon:
            action = env.action_space.sample()
        else:
            action = np.argmax(q_table[state])

        next_state, reward, terminated, truncated, _ = env.step(action)
        done = terminated or truncated

        q_table[state, action] += alpha * (
            reward + gamma * np.max(q_table[next_state]) - q_table[state, action]
        )

        state = next_state
        total_reward += reward

    rewards_per_episode.append(total_reward)
    epsilon = max(epsilon_min, epsilon * epsilon_decay)

avg_last_100 = np.mean(rewards_per_episode[-100:])
print(f"Average reward (last 100 episodes): {avg_last_100:.2f}")
```

After training, we can see the learned policy in action:


```
state, _ = env.reset()
env_render = gym.make("Taxi-v3", render_mode="ansi")
state, _ = env_render.reset()
done = False
total_reward = 0

while not done:
    action = np.argmax(q_table[state])
    state, reward, terminated, truncated, _ = env_render.step(action)
    done = terminated or truncated
    total_reward += reward

print(env_render.render())
print(f"Total reward: {total_reward}")
```

### Q-Learning Convergence

Q-Learning is guaranteed to converge to the optimal Q-values under two conditions:

1. Every state-action pair is visited infinitely often (exploration)
2. The learning rate decays appropriately (but not too fast)

In practice, epsilon-greedy with decay handles condition 1, and a fixed small learning rate often works well enough.

## SARSA

SARSA (State-Action-Reward-State-Action) is the on-policy counterpart to Q-Learning. The name comes from the quintuple $(S, A, R, S', A')$ used in the update.

The SARSA update rule:

$$Q(s, a) \leftarrow Q(s, a) + \alpha \cdot \left[r + \gamma \cdot Q(s', a') - Q(s, a)\right]$$

The critical difference from Q-Learning: **instead of using $\max_{a'} Q(s', a')$, SARSA uses $Q(s', a')$ — the Q-value of the action the agent actually takes next.** This makes SARSA on-policy: it learns the value of the policy it's currently following, including its exploration behavior.


```
env = gym.make("Taxi-v3")

q_table_sarsa = np.zeros((n_states, n_actions))
alpha = 0.1
gamma = 0.99
epsilon = 1.0
epsilon_min = 0.01
epsilon_decay = 0.995
num_episodes = 5000

sarsa_rewards = []

for episode in range(num_episodes):
    state, _ = env.reset()
    total_reward = 0
    done = False

    if np.random.random() < epsilon:
        action = env.action_space.sample()
    else:
        action = np.argmax(q_table_sarsa[state])

    while not done:
        next_state, reward, terminated, truncated, _ = env.step(action)
        done = terminated or truncated

        if np.random.random() < epsilon:
            next_action = env.action_space.sample()
        else:
            next_action = np.argmax(q_table_sarsa[next_state])

        q_table_sarsa[state, action] += alpha * (
            reward + gamma * q_table_sarsa[next_state, next_action]
            - q_table_sarsa[state, action]
        )

        state = next_state
        action = next_action
        total_reward += reward

    sarsa_rewards.append(total_reward)
    epsilon = max(epsilon_min, epsilon * epsilon_decay)

avg_last_100 = np.mean(sarsa_rewards[-100:])
print(f"SARSA average reward (last 100): {avg_last_100:.2f}")
```

### Q-Learning vs. SARSA

The key practical difference:

* **Q-Learning (off-policy):** Learns the optimal policy regardless of what exploration policy is used. It's more aggressive and can learn faster, but may take risky actions during training.
* **SARSA (on-policy):** Learns the value of the policy it's actually following, including exploration. It's more conservative and safer, which matters in real-world applications where exploration costs are high.

Think of it this way: Q-Learning is the optimistic student who always assumes they'll make the best choice next time. SARSA is the realistic student who accounts for the fact that they might explore (make mistakes) along the way.

## Monte Carlo Methods

Monte Carlo (MC) methods take a different approach: instead of updating Q-values after each step (like Q-Learning and SARSA), they wait until the end of an episode and use the actual returns observed.

The idea is simple: play many episodes, track the returns received after visiting each state-action pair, and average them.

### First-Visit Monte Carlo

First-visit MC updates $Q(s, a)$ using the return observed the first time $(s, a)$ is visited in an episode:


```
from collections import defaultdict

env = gym.make("Taxi-v3")

q_table_mc = np.zeros((n_states, n_actions))
returns_sum = defaultdict(float)
returns_count = defaultdict(int)

gamma = 0.99
epsilon = 1.0
epsilon_min = 0.01
epsilon_decay = 0.995
num_episodes = 10000

mc_rewards = []

for episode in range(num_episodes):
    episode_data = []
    state, _ = env.reset()
    done = False

    while not done:
        if np.random.random() < epsilon:
            action = env.action_space.sample()
        else:
            action = np.argmax(q_table_mc[state])

        next_state, reward, terminated, truncated, _ = env.step(action)
        done = terminated or truncated
        episode_data.append((state, action, reward))
        state = next_state

    G = 0
    visited = set()

    for state, action, reward in reversed(episode_data):
        G = reward + gamma * G

        if (state, action) not in visited:
            visited.add((state, action))
            returns_sum[(state, action)] += G
            returns_count[(state, action)] += 1
            q_table_mc[state, action] = (
                returns_sum[(state, action)] / returns_count[(state, action)]
            )

    mc_rewards.append(sum(r for _, _, r in episode_data))
    epsilon = max(epsilon_min, epsilon * epsilon_decay)
```

Every-visit MC is the same but updates for every time $(s, a)$ appears in an episode, not just the first. Both converge to the true Q-values, but first-visit has slightly better theoretical properties.

### Monte Carlo vs. Temporal Difference

MC methods have some notable characteristics:

* **No bootstrapping** — they use complete actual returns, not estimates
* **Higher variance** — returns can vary a lot between episodes
* **Lower bias** — they don't depend on initial value estimates
* **Only work for episodic tasks** — episodes must terminate
* **Can be slow to converge** — especially for long episodes

## Temporal Difference Learning

Temporal Difference (TD) methods combine ideas from both Monte Carlo and dynamic programming. They update estimates based on other estimates — a process called **bootstrapping**.

### TD(0)

The simplest TD method updates the value function after each step using:

$$V(s) \leftarrow V(s) + \alpha \cdot \left[r + \gamma \cdot V(s') - V(s)\right]$$

The term $r + \gamma \cdot V(s')$ is called the TD target, and $r + \gamma \cdot V(s') - V(s)$ is the TD error ($\delta$). Both Q-Learning and SARSA are actually TD methods — they just apply the TD idea to Q-values instead of V-values.

TD(0) has advantages over MC:

* Updates every step — doesn't need to wait for the episode to end
* Works for continuing tasks — not limited to episodic problems
* Lower variance — single-step updates are more stable
* Can bootstrap — learns from estimated values

### TD($\lambda$): Bridging MC and TD

TD($\lambda$) creates a smooth spectrum between TD(0) and Monte Carlo using eligibility traces. The parameter $\lambda$ controls the trade-off:

* $\lambda = 0 \rightarrow$ pure TD(0), one-step updates
* $\lambda = 1 \rightarrow$ equivalent to Monte Carlo, full-return updates
* $0 < \lambda < 1 \rightarrow$ a weighted combination of multi-step returns

In practice, values like $\lambda = 0.8$ or $\lambda = 0.9$ often work well, giving you the variance reduction of TD with some of the unbiased nature of MC.

## Putting It All Together

Let's compare Q-Learning and SARSA on the same problem to see how they differ in practice:


```
import matplotlib.pyplot as plt

def smooth_rewards(rewards, window=100):
    return [np.mean(rewards[max(0, i - window):i + 1]) for i in range(len(rewards))]

plt.figure(figsize=(12, 6))
plt.plot(smooth_rewards(rewards_per_episode), label="Q-Learning", alpha=0.8)
plt.plot(smooth_rewards(sarsa_rewards), label="SARSA", alpha=0.8)
plt.xlabel("Episode")
plt.ylabel("Average Reward (100-episode window)")
plt.title("Q-Learning vs SARSA on Taxi-v3")
plt.legend()
plt.grid(True)
plt.show()
```

## Summary

Reinforcement learning is a powerful paradigm where agents learn through interaction rather than from labeled data. Here are the key takeaways:

* **RL framework:** An agent interacts with an environment through states, actions, and rewards; the goal is to learn a policy that maximizes cumulative reward.
* **MDPs formalize RL** with states, actions, transition probabilities, rewards, and a discount factor $\gamma$.
* **Value functions $V(s)$ and $Q(s, a)$** estimate the expected return from states and state-action pairs; they're connected by the Bellman equations.
* **Exploration vs. exploitation** is the fundamental RL dilemma; epsilon-greedy, softmax, and UCB are common strategies.
* **Q-Learning is off-policy** — it learns optimal Q-values regardless of the exploration policy; uses max Q for updates.
* **SARSA is on-policy** — it learns the value of the policy it actually follows, making it more conservative and safer.
* **Monte Carlo methods** use complete episode returns for updates — no bootstrapping, but only work for episodic tasks.
* **TD Learning** updates after each step using bootstrapping; TD($\lambda$) bridges the gap between TD(0) and Monte Carlo.
