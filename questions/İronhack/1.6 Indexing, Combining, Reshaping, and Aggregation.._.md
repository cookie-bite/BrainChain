# Indexing, Combining, Reshaping, and Aggregation

## Introduction

Once your data is loaded and cleaned, the next challenge is shaping it into the structure your analysis needs. Real datasets are rarely organized exactly the way you want: observations may be split across multiple tables, columns may represent categories rather than variables, and you often need summaries at different levels of detail. This lesson builds a clear mental model for how to manipulate data with pandas so that you can combine datasets, reshape tables, and compute meaningful aggregations with confidence.

The core ideas here are alignment and intent. When you combine or reshape data, you are defining how different pieces of information relate. When you aggregate, you are deciding which level of detail matters for your question. The goal is to express those choices clearly in code so the resulting dataset tells the right story.

## Indexing as the Backbone of Combining

pandas aligns data primarily by index and column labels. This alignment behavior is what makes combining and reshaping both powerful and safe, but it also means you must be explicit about what the index represents. If you treat the index as "row numbers" when it actually identifies entities, you can accidentally misalign data.

Suppose you have two DataFrames representing different measurements for the same cities:


```
import pandas as pd

temp = pd.DataFrame({
    "city": ["Seoul", "Berlin", "Nairobi"],
    "temperature_c": [26.5, 18.2, 22.1]
}).set_index("city")

humidity = pd.DataFrame({
    "city": ["Seoul", "Berlin", "Toronto"],
    "humidity": [0.60, 0.65, 0.70]
}).set_index("city")
```

If you add these side by side with alignment, pandas matches on the index:


```
combined = temp.join(humidity, how="outer")
combined
```

The result includes all cities from both tables, with missing values where one table lacks a city. This is the default and most honest behavior, because it reflects the underlying data coverage instead of forcing a match that might be wrong.

## Combining Data with Concatenation

Concatenation stacks objects along a given axis. It is the right tool when you are appending rows or columns that share a common structure. For example, if you have monthly data in separate DataFrames, you can combine them by stacking rows:


```
jan = pd.DataFrame({"month": "Jan", "sales": [120, 150, 130]})
feb = pd.DataFrame({"month": "Feb", "sales": [140, 160, 155]})

all_sales = pd.concat([jan, feb], ignore_index=True)
all_sales
```

The `ignore_index=True` argument resets the index so you get a continuous range. This is often desirable when stacking row data from multiple sources. If you want to preserve source identity, you can add a key:


```
all_sales = pd.concat([jan, feb], keys=["Jan", "Feb"])
all_sales
```

Now the result has a hierarchical index that records the source. This is a powerful way to keep provenance while combining data.

Concatenation also works along columns:


```
left = pd.DataFrame({"city": ["Seoul", "Berlin"], "temp": [26.5, 18.2]})
right = pd.DataFrame({"humidity": [0.60, 0.65]})

combined = pd.concat([left, right], axis=1)
combined
```

In this case, pandas aligns by index position because the index is default and identical. If the index does not align, you get missing values. This reinforces the idea that index alignment matters in all combining operations.

## Joining and Merging: Relational Thinking

When data is split across tables with key columns, you use merge to combine them. The mental model is relational: you are matching rows based on key values. This is similar to SQL joins.

Suppose you have one table of city metadata and another of measurements:


```
cities = pd.DataFrame({
    "city": ["Seoul", "Berlin", "Nairobi"],
    "country": ["Korea", "Germany", "Kenya"]
})

measurements = pd.DataFrame({
    "city": ["Seoul", "Seoul", "Berlin", "Nairobi"],
    "temperature_c": [26.5, 27.0, 18.2, 22.1]
})

merged = pd.merge(measurements, cities, on="city", how="left")
merged
```

The `on="city"` argument specifies the key. The `how="left"` argument ensures that all rows from measurements are preserved, with country information added where available. This is typically what you want when your measurements are primary and metadata is supplementary.

If you choose `how="inner"`, you keep only matching keys. If you choose `how="outer"`, you keep all keys from both tables and fill missing values. The join type is a semantic decision about which rows should survive. Thinking clearly about that decision prevents subtle errors.

## Reshaping Data: Wide and Long

Many datasets are easier to analyze in long format, where each row is a single observation and each column is a variable. Others are easier to read in wide format, where categories become columns. Reshaping is the process of switching between these representations.

Suppose you have a wide table of quarterly sales:


```
sales_wide = pd.DataFrame({
    "city": ["Seoul", "Berlin"],
    "Q1": [120, 95],
    "Q2": [130, 100],
    "Q3": [125, 110],
    "Q4": [140, 115]
})
```

To convert to long format, use `melt`:


```
sales_long = sales_wide.melt(id_vars="city", var_name="quarter", value_name="sales")
sales_long
```

Now each row represents a single city-quarter pair. This format is often required for plotting and group-based analysis. The `melt` operation explicitly states which columns are identifiers and which columns contain values to unpivot.

To go back to wide format, use `pivot`:


```
sales_back = sales_long.pivot(index="city", columns="quarter", values="sales")
sales_back
```

Pivoting requires that each combination of index and column is unique. If there are multiple values for the same combination, you need `pivot_table`, which allows aggregation.

### Pivot Tables and Aggregation in One Step

`pivot_table` combines reshaping with aggregation, which is useful when your data has multiple observations per group. For example, if you have daily sales and want monthly averages:


```
daily = pd.DataFrame({
    "city": ["Seoul", "Seoul", "Berlin", "Berlin"],
    "month": ["Jan", "Jan", "Jan", "Jan"],
    "sales": [120, 130, 90, 100]
})

pivoted = daily.pivot_table(index="city", columns="month", values="sales", aggfunc="mean")
pivoted
```

The result is a wide table with city rows and month columns, where each value is the mean sales for that city-month. This is a common pattern for summary reporting and comparative analysis.

## GroupBy: Split, Apply, Combine

The `groupby` operation is the foundation of aggregation in pandas. The mental model is split-apply-combine: you split the data into groups, apply a function to each group, and then combine the results.

Suppose you want average temperature per city:


```
measurements = pd.DataFrame({
    "city": ["Seoul", "Seoul", "Berlin", "Nairobi", "Berlin"],
    "temperature_c": [26.5, 27.0, 18.2, 22.1, 19.0]
})

avg_temp = measurements.groupby("city")["temperature_c"].mean()
avg_temp
```

The result is a Series indexed by city. This is a succinct expression of the split-apply-combine process. The grouping key defines the split, and the aggregation defines the combine.

You can group by multiple keys:


```
measurements["month"] = ["Jan", "Feb", "Jan", "Jan", "Feb"]
avg_by_city_month = measurements.groupby(["city", "month"])["temperature_c"].mean()
avg_by_city_month
```

This produces a hierarchical index with both city and month. You can reset the index to get a flat table:


```
avg_by_city_month.reset_index()
```

This is often useful when you want to merge the aggregated results back into other DataFrames or use them for plotting.

### Aggregating Multiple Columns and Multiple Functions

Real analyses often require multiple summaries at once. You can aggregate multiple columns with different functions using `agg`:


```
summary = measurements.groupby("city").agg(
    mean_temp=("temperature_c", "mean"),
    min_temp=("temperature_c", "min"),
    max_temp=("temperature_c", "max")
)
summary
```

This produces a DataFrame with clear column names. The named aggregation syntax makes the intent explicit and avoids ambiguous column names. It also keeps the output tidy, which helps when you reuse the results downstream.

You can also aggregate with custom functions, but you should be cautious. Custom functions can be slower and harder to interpret. Use them when you need a measure that built-in functions do not provide, and document the logic clearly.

## Reshaping with MultiIndex

When you group and aggregate, pandas often returns a `MultiIndex`. This is a powerful structure for representing multi-level categories, but it can be confusing if you are not expecting it. The key is to treat the `MultiIndex` as a structured label rather than a simple row number.

For example:


```
avg_by_city_month = measurements.groupby(["city", "month"])["temperature_c"].mean()
avg_by_city_month
```

You can `unstack` to move one level into columns:


```
wide = avg_by_city_month.unstack("month")
wide
```

This is another path from long to wide, and it is often more convenient after `groupby` operations. The combination of `groupby`, `unstack`, and `reset_index` gives you flexible control over shape.

## Combining Aggregated Results Back to Detail

Sometimes you need to add group-level summaries back to the original data. `transform` is designed for this because it returns an output aligned with the original index:


```
measurements["city_avg"] = measurements.groupby("city")["temperature_c"].transform("mean")
measurements
```

Now each row includes the city average, which you can use for comparisons or normalization. This is different from `agg`, which reduces the data to one row per group. Understanding the difference between `agg` and `transform` is essential when you want to preserve the original detail.

## Closing Perspective

Indexing, combining, reshaping, and aggregation are the daily tools of data work. They are not just mechanical steps; they are the way you express analytical intent. Concatenation and joins define how datasets relate. Reshaping defines how your variables are represented. Groupby and aggregation define the level of insight you want to extract.

When you use these tools with a clear mental model, your code becomes both powerful and readable. You can move from raw, fragmented inputs to a clean, analysis-ready table that answers real questions. This is the skill that makes pandas valuable in applied data and AI work, and it will continue to pay off as your datasets and questions grow in complexity.
