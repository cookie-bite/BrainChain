# Training Deep Networks

## Loss Functions: What Are We Minimising?

A neural network learns by minimising a loss function $L(\hat{y}, y)$ that compares its prediction $\hat{y}$ to the ground-truth $y$. You've met losses before in classical ML — they're the same idea, just used inside a bigger model.

### Mean Squared Error (Regression)

For continuous targets:

$$L_{\text{MSE}} = \frac{1}{N} \sum_{i} (y_i - \hat{y}_i)^2$$

Symmetric, differentiable everywhere, sensitive to outliers. Default choice for regression. Mean Absolute Error is a robust alternative when outliers are real.

### Cross-Entropy (Classification)

For binary targets:

$$L_{\text{BCE}} = -\frac{1}{N} \sum_{i} [ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) ]$$

For $K$-class targets with one-hot labels:

$$L_{\text{CE}} = -\frac{1}{N} \sum_{i} \sum_{k} y_{i,k} \log(\hat{y}_{i,k})$$

Cross-entropy heavily penalises confident wrong answers (think of $\log(0.01)$ when the true class is class 1). It pairs naturally with sigmoid (binary) and softmax (multi-class) outputs.

A practical note: in PyTorch you should use `nn.CrossEntropyLoss`, which internally combines softmax + log + cross-entropy in a numerically stable way. Don't apply softmax yourself before feeding it to that loss.

## Backpropagation: Gradients, the Chain Rule, and All That

Once you have a loss, you need to know how each weight in the network influenced it. That's a derivative — and computing the derivative of the loss with respect to every weight is what backpropagation does.

### The Idea in One Diagram

A network is just a chain of operations. Read top-to-bottom for the forward pass, and read the same chain bottom-to-top for the backward pass:

```
   FORWARD PASS  (top → bottom)
        x
        │
        ▼
   z₁ = W₁ x + b₁          ← parameters W₁, b₁
        │
        ▼
   h₁ = f(z₁)              ← hidden activation, e.g. ReLU
        │
        ▼
   z₂ = W₂ h₁ + b₂         ← parameters W₂, b₂
        │
        ▼
   ŷ  = g(z₂)              ← output activation (sigmoid / softmax / identity)
        │
        ▼
   L  = loss(ŷ, y)         ← scalar loss

```

Start with $\frac{\partial L}{\partial L} = 1$ and walk back up the same chain, multiplying local derivatives at each step:

$$\frac{\partial L}{\partial \hat{y}} \rightarrow \frac{\partial L}{\partial z_2} \rightarrow \frac{\partial L}{\partial h_1} \rightarrow \frac{\partial L}{\partial z_1} \rightarrow \frac{\partial L}{\partial x}$$

At any parameter, that walk gives a single product, e.g.

$$\frac{\partial L}{\partial W_1} = \frac{\partial L}{\partial z_2} \cdot \frac{\partial z_2}{\partial h_1} \cdot \frac{\partial h_1}{\partial z_1} \cdot \frac{\partial z_1}{\partial W_1}$$

The optimiser only needs the gradients w.r.t. parameters — $\frac{\partial L}{\partial W_1}$, $\frac{\partial L}{\partial b_1}$, $\frac{\partial L}{\partial W_2}$, $\frac{\partial L}{\partial b_2}$ — and uses them for the SGD update. The other gradients are just intermediates along the way.

That's the chain rule in action: to know how a tiny change in any parameter affects the loss, you multiply together the local derivatives along the path from that parameter down to the loss. Backprop just organises this calculation efficiently:

1. **Forward pass** — compute and cache every intermediate value (preactivations, activations).
2. **Backward pass** — start from the loss, compute the gradient of the loss w.r.t. the output, and propagate gradients backwards through each layer using the chain rule.

Each layer ends up with $\frac{\partial L}{\partial W}$ and $\frac{\partial L}{\partial b}$ — exactly what gradient descent needs.

The reason backprop is fast is that it reuses partial results. A naive symbolic approach would compute many of the same chain-rule terms over and over; backprop visits each node once.

### What You Actually Need to Do

In PyTorch, all of this is one line:


```
loss.backward()
```

That's it. PyTorch builds a computational graph as your forward pass runs, and `.backward()` walks that graph in reverse, populating the `.grad` attribute on every parameter. Frameworks like TensorFlow and JAX do something equivalent. Knowing the idea of backpropagation is essential; implementing it by hand for every model is no longer your job.

You should still understand the shapes involved, because shape errors are the #1 source of bugs in deep learning. A useful reminder: gradients always have the same shape as the parameter they belong to. If `W1.shape == (8, 30)`, then `W1.grad.shape == (8, 30)`.

### The Training Loop

Here's the canonical PyTorch training loop. It's worth memorising — every project you'll ever build is some variation of this:


```
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
loss_fn = nn.BCELoss()

for epoch in range(n_epochs):
    for batch_x, batch_y in train_loader:
        optimizer.zero_grad()           # 1. clear old gradients
        y_hat = model(batch_x)          # 2. forward pass
        loss = loss_fn(y_hat, batch_y)  # 3. compute loss
        loss.backward()                 # 4. backward pass (autograd)
        optimizer.step()                # 5. update weights
```

Five steps. Five lines. Every "advanced" piece of training code you'll ever read is built on top of this skeleton.

#### Why Step 1 (zero_grad) Matters

PyTorch accumulates gradients by default. If you forget `zero_grad()`, you'll add the new mini-batch's gradient to last batch's gradient and your training will silently misbehave. This is the single most common bug for beginners.

## Gradient Descent: Batch, Mini-Batch, SGD

Now to the optimiser — the thing that turns gradients into weight updates. The basic update rule is:

$$W \leftarrow W - \eta \cdot \nabla_W L$$

where $\eta$ is the learning rate. The variants differ in how much data you look at before each update.

| Variant | Data per update | Pros | Cons |
| --- | --- | --- | --- |
| **Batch GD** | Entire training set | Smooth gradient | Slow, doesn't fit in memory for large data |
| **SGD** | One example | Fast, noisy gradient escapes shallow minima | Very noisy, hard to vectorise |
| **Mini-batch GD** | A batch of N samples (32–512 typical) | Best of both worlds | Need to choose batch size |

Mini-batch is the practical default, with batch size usually between 32 and 256. Smaller batches give noisier but more frequent updates; larger batches are computationally efficient but can converge to flatter, less generalising minima. A common starting point is 32 or 64.

## Beyond Plain SGD: Smarter Optimisers

Plain SGD often struggles in practice. The loss landscape of a deep network is full of ravines, saddle points, and curved valleys where a constant learning rate is either too small (slow) or too big (oscillating). Modern optimisers fix this with various tricks.

### Momentum

Add an "inertia" term that smooths updates over time:

$$v_t = \beta \cdot v_{t-1} + \nabla_W L$$

$$W \leftarrow W - \eta \cdot v_t$$

Imagine a ball rolling down a hilly surface — it builds up speed in directions that consistently slope downhill. Momentum (typically $\beta = 0.9$) gives SGD a similar memory.

### RMSProp

Adapt the learning rate per parameter based on a running average of squared gradients:

$$s_t = \beta \cdot s_{t-1} + (1 - \beta) \cdot (\nabla_W L)^2$$

$$W \leftarrow W - \frac{\eta}{\sqrt{s_t} + \varepsilon} \cdot \nabla_W L$$

Parameters that consistently see large gradients get smaller updates; quiet parameters get bigger updates. Works well on noisy, non-stationary problems.

### Adam (the popular default)

Adam = Momentum + RMSProp. It maintains running averages of both gradients (first moment) and squared gradients (second moment) and uses both:


```
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
```

In practice, Adam with `lr=1e-3` is a sane default for almost every problem. It's not always optimal — well-tuned SGD with momentum sometimes wins for image models — but it converges robustly and that's what matters when you're starting out.

## Learning Rate Schedules

The single most important hyperparameter in deep learning is the learning rate. Too high and your training diverges. Too low and it crawls. The trick is that the best learning rate often changes during training — high at first to make rapid progress, low later to refine.

The cleanest fix is a schedule that lowers the learning rate over time. Common choices:

* **Step decay** — multiply LR by 0.1 every N epochs
* **Cosine annealing** — smoothly decay from $\eta_{\text{max}}$ to $\eta_{\text{min}}$ following a cosine curve
* **Warmup** — start with a tiny LR, ramp up over the first few hundred steps, then decay


```
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=50)

for epoch in range(50):
    train_one_epoch(...)
    scheduler.step()
```

For most projects, "Adam + cosine annealing" is hard to beat as a starting recipe.

## Stopping Overfitting: The Regularisation Toolkit

Deep networks have far more parameters than data points in most realistic problems. Without regularisation, they happily memorise training data and fail on test data. Modern training relies on a small toolkit of complementary techniques.

### Weight Initialisation

Where you start matters. With sigmoid/tanh activations, Xavier (Glorot) initialisation keeps the variance of activations roughly constant across layers:

$$W \sim \mathcal{N}\left(0, \sqrt{\frac{1}{\text{fan\_in}}}\right)$$

With ReLU, He initialisation is the right adjustment:

$$W \sim \mathcal{N}\left(0, \sqrt{\frac{2}{\text{fan\_in}}}\right)$$

PyTorch's default for `nn.Linear` is already a sensible variant. You'll rarely need to set this manually — but knowing why it matters helps you debug a network that's stuck on day one.

### Dropout

During training, randomly set a fraction of activations to zero. This forces the network to not rely on any single neuron, which acts like training an ensemble of slightly different networks every batch.


```
self.dropout = nn.Dropout(p=0.5)
```

During inference, dropout is disabled and outputs are scaled appropriately — PyTorch handles this automatically when you call `model.eval()`. A typical dropout rate is 0.1–0.5 and it's almost always applied after activations.

### Batch Normalisation

Normalise the activations of each layer to have zero mean and unit variance, then learn to scale and shift them:

$$\hat{a} = \gamma \cdot \frac{a - \mu_{\text{batch}}}{\sigma_{\text{batch}}} + \beta$$

BatchNorm has two big effects: it stabilises training (you can use larger learning rates) and acts as a mild regulariser (each mini-batch sees slightly different statistics). It's almost a must-have for deep convolutional networks. The PyTorch primitives are `nn.BatchNorm1d`, `nn.BatchNorm2d`.

### Early Stopping

Watch validation loss. The moment it starts going up while training loss keeps going down, stop. That's where the network has begun to overfit.


```
if val_loss < best_val_loss:
    best_val_loss = val_loss
    patience_counter = 0
    save_checkpoint(model)
else:
    patience_counter += 1
    if patience_counter >= patience:
        break
```

Early stopping is essentially free — it only costs you a validation set — and it's one of the most reliable regularisation techniques.

### Data Augmentation

Generate "new" training examples by applying random label-preserving transformations to existing ones. For images: flips, rotations, crops, colour jitter. For text: synonym replacement, random masking. Augmentation increases effective dataset size and forces the model to be invariant to nuisance variations in the data.


```
from torchvision import transforms

train_tf = transforms.Compose([
    transforms.RandomHorizontalFlip(),
    transforms.RandomCrop(32, padding=4),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.5]*3, std=[0.5]*3),
])
```

This is one of the highest-ROI techniques you'll learn. We'll lean on it heavily for the cat-detection assessment on Friday.

## Hyperparameter Tuning: A Practical Order

You will face an avalanche of hyperparameters: learning rate, batch size, number of layers, hidden size, dropout rate, weight decay, optimiser, and so on. Tune them in roughly this order:

1. **Learning rate** — by far the most important. Try $10^{-2}$, $10^{-3}$, $10^{-4}$ first.
2. **Architecture size** — number of layers and hidden units.
3. **Regularisation** — dropout rate, weight decay.
4. **Optimiser & schedule** — Adam vs SGD+momentum, cosine vs step.
5. **Batch size** — last; usually pick 32–128 unless GPU memory forces otherwise.

Random search beats grid search for this kind of tuning, and for serious projects tools like Optuna or Ray Tune automate the search.

## Frameworks: PyTorch vs Keras

You'll see two frameworks dominating deep learning in 2026: PyTorch (research-favourite, increasingly dominant in industry) and Keras / TensorFlow (still widely used, especially in production at large companies).

We'll use PyTorch for the rest of this unit. It is more "Pythonic" — the model is just a class, the training loop is normal Python, and debugging looks like debugging any other code. Keras wraps a similar set of ideas in a more declarative API; if you can build models in PyTorch, learning Keras later is a few hours of work.

## Putting It Together

Here's the recipe you'll use for every deep learning project from now on:

1. Define your model (`nn.Module` subclass)
2. Pick a loss function (`nn.CrossEntropyLoss`, `nn.MSELoss`, …)
3. Pick an optimiser (`torch.optim.Adam` is a fine default)
4. Pick a learning rate schedule (cosine annealing or step decay)
5. Add regularisation (dropout, batch normalisation, weight decay, augmentation, early stopping)
6. Run the training loop with mini-batches
7. Track training and validation loss; tune hyperparameters; iterate

This recipe is genuinely most of what you need to know about training deep networks. The rest of this unit will customise it for specific problem types — vision, sequences, generative models — but the skeleton stays the same.

## Summary

Training a neural network is gradient descent on a clever loss function. The pieces you met today:

* **Loss functions match the task:** MSE for regression, cross-entropy for classification.
* **Backpropagation is the chain rule, automated by frameworks;** you write the forward pass and one call to `.backward()` does the rest.
* **The training loop has five canonical steps:** zero gradients, forward, loss, backward, step.
* **Mini-batch SGD is the workhorse;** Adam is the smart default optimiser.
* **Learning rate schedules** — especially cosine annealing or warmup-then-decay — make a big practical difference.
* **Regularisation matters even more than for classical ML:** dropout, batch normalisation, weight init, early stopping, and data augmentation are the standard toolkit.
* **PyTorch is the framework we'll use;** the same ideas transfer to Keras with minor syntax changes.

In today's lab you'll wire all of this together and train a small MLP on the Fashion-MNIST dataset, watching the loss curves tell you a story about overfitting, dropout, and learning-rate choice.
