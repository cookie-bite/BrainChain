# Built-in Data Structures, Functions, and Files

## Introduction

In applied data work, you live inside collections of values. You gather rows from a CSV file, group them by a key, compute statistics, and write results back out for others to use. The way you represent those collections in Python has a direct effect on correctness, clarity, and performance. This lesson builds the core mental models for Python’s built-in data structures, how to write and use functions to organize logic, and how to work with files as a bridge between data on disk and data in memory. The goal is not to memorize syntax, but to understand why each structure exists, how it behaves, and when it is the right tool.

We will move from the simplest sequence types to dictionaries and sets, then to control flow and functions as a way to express transformations. Finally, we will connect these ideas to file I/O and structured data in text form. If you can reason about how Python stores and manipulates data at this level, you can build reliable analysis code that scales from small experiments to larger pipelines.

## Lists: The Workhorse Sequence

Lists are ordered, mutable sequences. They are often the first container you use to hold values, especially when order matters and you plan to add, remove, or update elements. The crucial mental model is that a list is a container whose elements live in order and can change over time. This makes lists great for intermediate steps, but less ideal for cases where you need fast lookups by key or fixed-size numeric computation.

Here is a small list of daily temperatures:


```
temps_c = [21.1, 22.4, 20.8, 19.9, 23.0]
temps_c
```

This list preserves the order of measurements. If you want to add a new day’s temperature, you can append it:


```
temps_c.append(22.2)
temps_c
```

The list grows because it is mutable. This is useful in data collection workflows, such as accumulating values from a loop or a stream. But it also means you need to be careful about shared references. If two variables point to the same list, a change through one name affects the other because the underlying object is the same.

Lists support slicing, which lets you select subsequences. Slicing returns a new list:


```
weekdays = temps_c[:5]
weekdays
```

This creates a new list of the first five entries. This behavior matters when you want a snapshot of data at a specific point in time; slicing gives you a separate object rather than a view into the same list. That distinction helps prevent accidental side effects.

## Tuples: Fixed Sequences and Structural Meaning

Tuples look like lists but represent fixed-size sequences. The mental model is that a tuple is a record of values whose position carries meaning. You use tuples when you want to express structure rather than a mutable container.

Consider a coordinate pair:


```
point = (37.57, 126.98)
point
```

You can still index a tuple:


```
lat = point[0]
lon = point[1]
```

The difference is that you cannot change the tuple in place. This immutability makes tuples suitable as dictionary keys, and it communicates intent: “this object represents a fixed structure.” In data analysis, tuples are often used for rows of data, multi-part keys, or structured return values from functions.

Another common use is unpacking:


```
city, temp = ("Toronto", 16.7)
city
```

Unpacking lets you take a structured sequence and bind its parts to names. This makes code more readable and reduces indexing noise. It is especially helpful when iterating over sequences of pairs or triples, such as records loaded from a file.

## Dictionaries: Mapping from Keys to Values

Dictionaries are central to data analysis because they model key–value relationships. The mental model is that a dictionary maps a key to a value with fast lookup. When you need to associate labels with values, or store data that naturally has named fields, dictionaries are the right tool.

Here is a dictionary representing a single observation:


```
record = {"city": "Berlin", "temperature_c": 18.2, "humidity": 0.65}
record
```

You can access values by key:


```
record["temperature_c"]
```

This is more expressive than index-based access because the key names describe the data. It also supports flexible structures where not all records have the same fields, which is common in real-world data. If you need to add a new field, you just assign a new key:


```
record["temperature_f"] = record["temperature_c"] * 9 / 5 + 32
record
```

The dictionary grows dynamically. This is convenient but demands discipline: if your analysis expects a certain key to exist, you need to ensure it is created or handle missing keys carefully. A common pattern is to use `get` with a default:


```
record.get("pressure", None)
```

This returns `None` if the key is missing instead of raising an error. That makes dictionary access safer when working with incomplete data.

## Sets: Membership and Uniqueness

Sets represent unordered collections of unique elements. The mental model is that a set is about membership, not order. If you need to know whether a value appears, or you want to remove duplicates, a set is ideal.

Suppose you are working with a list of user IDs and want to know how many unique users there are:


```
user_ids = [101, 103, 101, 104, 103, 105]
unique_users = set(user_ids)
unique_users
```

The set removes duplicates. You can test membership quickly:


```
103 in unique_users
```

This returns `True` because sets are optimized for membership checks. This matters when you have large datasets and need fast lookup without scanning the whole list.

Sets also support operations like intersection and union:


```
group_a = {101, 102, 103}
group_b = {103, 104, 105}
group_a & group_b
```

The result contains elements in both sets. This mirrors common data analysis tasks, such as finding overlapping user cohorts or shared categories between datasets.

## Strings: Text as Data

In data work, text is often data, not just labels. Strings are sequences of characters, but the more useful mental model is that strings are immutable text objects with powerful methods for cleaning and parsing.

Consider a raw CSV line:


```
line = "Berlin,18.2,0.65"
parts = line.split(",")
parts
```

The `split` method turns the string into a list of fields. Because strings are immutable, methods like `split` and `replace` return new strings instead of modifying the original. This immutability makes string operations safe in pipelines, as you do not risk changing the original data unintentionally.

If you need to clean whitespace:


```
raw_city = "  Berlin "
city = raw_city.strip()
city
```

This returns a new, cleaned string. Understanding that strings are immutable helps you avoid mistakes such as assuming a method modifies a string in place.

## Control Flow: Expressing Logic Clearly

Data analysis involves decisions: filter values, branch on categories, and handle missing data. Python’s control flow constructs give you the language to express those decisions. The mental model is that control flow directs which statements run based on conditions and repetition.

Here is a simple filtering example:


```
temps_c = [21.1, 22.4, 20.8, 19.9, 23.0]
high_temps = []
 
for t in temps_c:
    if t >= 22.0:
        high_temps.append(t)
 
high_temps
```

The `for` loop iterates through each temperature. The `if` statement checks the condition and appends qualifying values. This is clear and correct, though not always the most efficient. In many cases, list comprehensions can express the same idea more concisely:


```
high_temps = [t for t in temps_c if t >= 22.0]
high_temps
```

Both produce the same result. The choice between them should be guided by readability and complexity. For simple filtering, a comprehension is concise and readable. For more complex logic, an explicit loop is often clearer.

## Functions: Encapsulating Transformations

Functions are the primary tool for packaging logic in Python. The mental model is that a function takes inputs, transforms them, and returns outputs. This encapsulation helps you reuse logic, test it independently, and reason about your code in smaller pieces.

Here is a function that converts a list of Celsius temperatures to Fahrenheit:


```
def c_to_f(values):
    return [v * 9 / 5 + 32 for v in values]
 
temps_f = c_to_f([21.1, 22.4, 20.8])
temps_f
```

The function takes a list of numbers, uses a list comprehension to apply the formula, and returns a new list. This works because list comprehensions apply the expression to each element and build a new list. The function expresses intent clearly and makes it easy to reuse the conversion elsewhere.

Functions can also accept optional parameters:


```
def clip(values, lower=None, upper=None):
    result = []
    for v in values:
        if lower is not None and v < lower:
            v = lower
        if upper is not None and v > upper:
            v = upper
        result.append(v)
    return result
 
clip([1, 5, 10, 20], lower=3, upper=12)
```

The `lower` and `upper` parameters default to `None`, which indicates no bound. This pattern makes the function flexible: it can clip on either side or both. The explicit checks against `None` ensure that you only apply a bound if it was provided. This is a common pattern in data cleaning functions where optional behavior is needed.

Understanding how functions handle arguments helps you avoid subtle errors. Python supports positional and keyword arguments. When a function has many parameters, using keywords improves clarity and reduces mistakes about parameter order.

## Anonymous Functions and Higher-Order Patterns

In data analysis, you often pass small pieces of logic into other functions, such as sorting or mapping. Anonymous functions created with `lambda` are a compact way to express such logic. The mental model is that a `lambda` creates a function object without binding it to a name.

Suppose you have a list of records and want to sort by temperature:


```
records = [
    {"city": "Seoul", "temperature_c": 26.5},
    {"city": "Berlin", "temperature_c": 18.2},
    {"city": "Nairobi", "temperature_c": 22.1}
]
 
sorted_records = sorted(records, key=lambda r: r["temperature_c"])
sorted_records
```

The `sorted` function expects a key function that extracts the value to sort by. The `lambda` provides that logic inline. This is often more readable than defining a separate named function for one-off use. However, if the logic becomes complex, a named function is clearer and easier to test.

Higher-order functions like `map` and `filter` also accept functions as arguments. In modern Python, list comprehensions often read more naturally, but the underlying idea is the same: you pass behavior into a function that applies it across data.

## Iteration Protocols and Generator Patterns

When working with large datasets, you do not always want to load everything into memory. Python’s iteration model allows you to process data one item at a time. Generators and iterators are essential for memory-efficient workflows.

A generator expression looks like a list comprehension but uses parentheses:


```
values = (v * v for v in range(5))
values
```

This does not create a list. It creates a generator that yields values on demand. You can iterate through it:


```
for v in values:
    print(v)
```

This prints each squared value without storing them all at once. This pattern is especially useful when reading large files or processing streaming data. It allows your analysis to scale beyond memory limits.

## Working with Files: Reading and Writing Text

Real data often lives in files, and Python provides straightforward tools for reading and writing text. The mental model is that a file is a stream of text or bytes, and you can iterate through it line by line.

Here is a basic file read:


```
with open("data/cities.csv", "r", encoding="utf-8") as f:
    lines = f.readlines()
lines[:3]
```

The `with` statement ensures the file is closed after the block finishes, even if an error occurs. This is crucial for correctness and resource management. `readlines()` reads all lines into memory, which is fine for small files but not ideal for large ones. For large files, iterate line by line:


```
with open("data/cities.csv", "r", encoding="utf-8") as f:
    for line in f:
        fields = line.strip().split(",")
        # process fields here
```

This approach is memory-efficient because it reads one line at a time. The `strip()` removes trailing newline characters, and `split(",")` parses the fields. This is a foundational pattern for text-based data ingestion.

Writing to a file follows a similar pattern:


```
rows = ["city,temperature_c,humidity", "Berlin,18.2,0.65", "Nairobi,22.1,0.58"]
 
with open("data/output.csv", "w", encoding="utf-8") as f:
    for row in rows:
        f.write(row + "\n")
```

Each row is written as a line of text. This pattern is simple and direct, and it connects your in-memory structures to files that can be used by other tools. When you get more advanced, you will use libraries like pandas for robust file handling, but the underlying concepts remain the same.

## Parsing Structured Text into Data Structures

To move from raw text to usable structures, you often parse lines into dictionaries or tuples. This is where earlier data structure concepts become practical.

Suppose your file has a header and data rows:


```
lines = [
    "city,temperature_c,humidity",
    "Berlin,18.2,0.65",
    "Nairobi,22.1,0.58"
]
 
header = lines[0].split(",")
records = []
 
for line in lines[1:]:
    values = line.split(",")
    record = dict(zip(header, values))
    records.append(record)
 
records
```

The `zip` function pairs each header with its corresponding value. `dict` then turns those pairs into a dictionary. This creates a list of dictionaries, a common pattern for tabular data before it is loaded into higher-level structures. The benefit is that each row becomes a self-describing object, which makes your code more readable and robust to changes in column order.

If you need numeric values, you must convert them explicitly:


```
for record in records:
    record["temperature_c"] = float(record["temperature_c"])
    record["humidity"] = float(record["humidity"])
```

This conversion is essential because data read from text files is always string-based. The explicit conversion step makes your data ready for computation and reduces errors later in the workflow.

## Putting It All Together

By now, you have a full toolkit for representing data in memory, applying transformations through functions, and connecting your analysis to data stored in files. Lists and tuples give you ordered sequences, dictionaries map keys to values, sets model unique membership, and strings carry text data. Control flow lets you apply logic, and functions package transformations into reusable pieces. File I/O connects all of this to real data on disk.

The most important takeaway is that these pieces are not separate topics. They are a coherent system. When you read a file, you parse it into structures. When you transform data, you rely on functions and control flow. When you need speed or clarity, you choose the right structure. This mental model is what makes Python effective for data analysis, and it will continue to guide you as you move into higher-level libraries and larger datasets.
