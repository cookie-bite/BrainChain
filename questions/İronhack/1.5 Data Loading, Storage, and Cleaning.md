# Data Loading, Storage, and Cleaning

## Introduction

Data analysis begins long before modeling or visualization. The most time-consuming and error-prone part of the workflow is often getting data into the right shape, with the right types, and with a clear record of what changed along the way. This lesson builds the mental model for loading data from common formats, storing intermediate results, and cleaning messy values without losing track of meaning. You will learn how to read structured text, handle missing values, standardize types, and design transformations that are transparent and reproducible.

The core idea is that data cleaning is not a single step. It is a sequence of small, intentional decisions. Each decision should be explicit, traceable, and grounded in how the data will be used. By the end, you should be able to load data confidently, inspect it for common issues, and apply cleaning operations that preserve correctness.

> **Data loading and cleaning flow:** raw files $\rightarrow$ loading $\rightarrow$ cleaning $\rightarrow$ analysis-ready data

## Reading Structured Text Files

Most datasets arrive as text, often in CSV or TSV format. pandas provides `read_csv` as the workhorse function for reading these files. The key is that you should treat file parsing as a controlled process, not a blind import. The parameters you pass determine how rows are interpreted, how missing values are recognized, and how types are inferred.


```
import pandas as pd

df = pd.read_csv("data/sales.csv")
df.head()
```

This reads the file and returns a DataFrame. `head()` shows the first few rows to confirm that the data looks reasonable. A good habit is to check column names, row counts, and the general shape early, before you trust the data.

If your file uses a different delimiter, you can specify it:


```
df = pd.read_csv("data/sales.tsv", sep="\t")
```

If the file has no header row, you can provide column names:


```
df = pd.read_csv("data/measurements.csv", header=None,
                 names=["city", "temperature_c", "humidity"])
```

These parameters make the parsing explicit, which reduces ambiguity and helps future readers understand how the data was interpreted.

## Parsing Dates and Custom Missing Values

Dates are a frequent source of errors because they are stored as strings in files. If you parse them as strings, time-based operations become harder and error-prone. pandas can parse dates during load:


```
df = pd.read_csv("data/sales.csv", parse_dates=["date"])
df.dtypes
```

Now `date` is a datetime type, which supports time-based indexing and resampling later. Parsing dates at load time is usually safer than converting after the fact because it makes the transformation explicit and consistent.

Missing values can also be encoded in many ways, such as "NA", "NULL", or "-". You can tell pandas which tokens should be treated as missing:


```
df = pd.read_csv("data/sales.csv", na_values=["NA", "NULL", "-"])
```

This converts those tokens to `NaN`, which is pandas' standard representation for missing values. Recognizing missing values early keeps your cleaning logic consistent.

## Inspecting Data Types and Basic Validation

After loading, you should inspect data types and check for inconsistencies. This is where `dtypes`, `info()`, and `describe()` become valuable.


```
df.info()
```

The output tells you the number of non-null values per column and the inferred data types. If a numeric column is read as object, that is a red flag. It usually means there are non-numeric values or formatting issues.

You can also do lightweight validation:


```
df["temperature_c"].min(), df["temperature_c"].max()
```

If the values are outside a reasonable range, you might have parsing issues, unit mismatches, or data errors. These checks are part of a disciplined workflow that catches problems early.

## Reading JSON and Other Semi-Structured Formats

Not all data is tabular. JSON files are common for APIs and nested data. pandas can read line-delimited JSON directly:


```
df = pd.read_json("data/events.json", lines=True)
```

Line-delimited JSON means each line is a separate JSON object, which maps naturally to rows in a DataFrame. If the JSON is nested, you may need to normalize it:


```
import json

with open("data/events_nested.json", "r", encoding="utf-8") as f:
    records = json.load(f)

df = pd.json_normalize(records)
df.head()
```

Normalization flattens nested structures into columns. This is useful for analysis, but it is also a design decision. You should consider which parts of the nested structure are relevant and how flattening affects meaning.

## Writing Data to Disk

Storing intermediate results is part of a reproducible workflow. You may want to save a cleaned dataset, or export results for downstream tools. pandas supports several formats.


```
df.to_csv("data/clean_sales.csv", index=False)
```

This writes the DataFrame back to CSV without the index. The `index=False` argument prevents the index from becoming an extra column. This is a common choice when the index is not meaningful or when you want to preserve the original column structure.

For larger datasets or faster I/O, formats like Parquet can be useful:


```
df.to_parquet("data/clean_sales.parquet")
```

Parquet preserves data types and is more efficient for large data. If you use Parquet, make sure your environment includes the required dependencies.

## Handling Missing Data

Missing values are inevitable. The key is to decide whether to remove, fill, or keep them based on your analytical goals. pandas gives you explicit tools to inspect missingness.


```
df.isna().sum()
```

This counts missing values by column. You can drop rows with missing values:


```
df_dropped = df.dropna()
```

Or fill them with a chosen value:


```
df_filled = df.fillna({"temperature_c": df["temperature_c"].mean()})
```

Filling with a mean is common, but it is not always appropriate. The right strategy depends on context. The key is to make the decision explicit and explainable.

## Cleaning and Transforming Values

Cleaning often involves standardizing strings, fixing inconsistent categories, and converting types. Suppose you have a column with extra whitespace and inconsistent capitalization:


```
df["city"] = df["city"].str.strip().str.title()
```

This removes whitespace and standardizes capitalization. String methods are vectorized in pandas, so they apply efficiently across the column.

Type conversion is also common:


```
df["humidity"] = pd.to_numeric(df["humidity"], errors="coerce")
```

`to_numeric` converts strings to numbers, and `errors="coerce"` turns invalid entries into `NaN`. This is a safe way to handle dirty input because it preserves the position of problematic values while making the column numeric.

## Handling Duplicates and Inconsistent Records

Duplicates can arise from data collection or merging. pandas makes it easy to detect and remove them:


```
df.duplicated().sum()
```

You can remove duplicates based on all columns or a subset:


```
df = df.drop_duplicates(subset=["city", "date"])
```

This keeps the first occurrence of each (city, date) pair. The choice of subset reflects your definition of uniqueness, which should be based on domain knowledge.

## Replacing Values and Recoding Categories

Recoding is common when values are inconsistent or too granular. Suppose you want to standardize category labels:


```
mapping = {"nyc": "New York", "new york": "New York", "NY": "New York"}
df["city"] = df["city"].replace(mapping)
```

This brings multiple labels into a single canonical form. The mapping makes the transformation explicit, which is important for transparency. Another approach is to use `where` to apply conditional replacements:


```
df["temperature_c"] = df["temperature_c"].where(df["temperature_c"] < 60, pd.NA)
```

Here, any value above 60 is treated as missing because it is likely an error in Celsius. This is a realistic data cleaning rule that reflects a domain constraint.

## Outliers and Data Quality Checks

Outliers are not always errors, but they should be examined. A simple way to flag them is to use quantiles:


```
low, high = df["temperature_c"].quantile([0.01, 0.99])
outliers = df[(df["temperature_c"] < low) | (df["temperature_c"] > high)]
outliers.head()
```

This identifies the most extreme values. You can then decide whether to keep, cap, or remove them based on the context. The key is that you are making a deliberate decision rather than applying a blanket rule.

## Building a Reproducible Cleaning Pipeline

Cleaning should be repeatable. That means each transformation should be coded, not done manually. You can chain operations to make the pipeline clear:


```
df = (
    pd.read_csv("data/sales.csv", parse_dates=["date"], na_values=["NA", "NULL", "-"])
      .drop_duplicates()
      .assign(
          city=lambda x: x["city"].str.strip().str.title(),
          humidity=lambda x: pd.to_numeric(x["humidity"], errors="coerce")
      )
)
```

This pattern reads the data, removes duplicates, and cleans columns in a single expression. The `assign` method is useful because it lets you create or transform columns while keeping the pipeline readable. The lambdas ensure that the transformations refer to the current DataFrame rather than a stale one.

The point is not to compress everything into one line, but to make the sequence of steps explicit. This is what allows others to understand and reproduce your results.

## Closing Perspective

Loading, storing, and cleaning data are foundational skills. The tools are straightforward, but the reasoning behind them is what makes them effective. You need to be explicit about parsing rules, careful about types, and intentional about how you handle missing values and outliers. When you build a disciplined cleaning process, you protect the integrity of your analysis and make your work reproducible.

As you move forward, these patterns will remain the backbone of your workflow. Whether you are preparing data for modeling, building dashboards, or running experiments, the same principles apply: load carefully, inspect early, clean deliberately, and document the transformations in code.
