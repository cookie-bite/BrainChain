# Chi-Square Tests and Power Analysis

## Introduction

In the previous lesson, you learned how to test hypotheses about means using t-tests. But not all interesting questions involve means. When you want to know whether customer preferences differ across regions, whether a marketing channel affects which product category people buy, or whether observed frequencies match your expectations, you need a different tool. The chi-square test is designed for exactly these situations: testing hypotheses about categorical data.

This lesson also introduces power analysis, which answers a question that every hypothesis test raises but rarely addresses: "If there is a real effect, how likely am I to detect it?" Power analysis connects sample size, effect size, significance level, and statistical power into a framework that helps you design experiments that actually have a chance of answering your question. By the end, you will be able to run chi-square tests for goodness of fit and independence, calculate effect sizes for categorical data, perform power analyses, and apply these tools to practical scenarios like A/B testing.

## Chi-Square Goodness-of-Fit Test

The goodness-of-fit test asks whether observed frequencies match a set of expected frequencies. In other words: "Does the data follow the pattern I expect?"

### The Intuition

Imagine you roll a die 600 times and record the results. If the die is fair, you would expect about 100 rolls for each face. But you might observe 95, 108, 87, 112, 102, and 96. Are these deviations from 100 just random noise, or evidence that the die is loaded?

The chi-square statistic measures how far the observed counts are from the expected counts, relative to what you would expect from random variation alone.


```
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from scipy import stats

# Example: testing whether a die is fair
np.random.seed(42)

# Observed counts from 600 rolls (slightly loaded die)
observed = np.array([85, 95, 110, 108, 102, 100])
n_rolls = observed.sum()
expected = np.array([100, 100, 100, 100, 100, 100])

print(f"Total rolls: {n_rolls}")
print(f"Observed: {observed}")
print(f"Expected: {expected}")

# Chi-square test
chi2_stat, p_value = stats.chisquare(observed, f_exp=expected)
print(f"\nChi-square statistic: {chi2_stat:.4f}")
print(f"p-value: {p_value:.4f}")
print(f"Degrees of freedom: {len(observed) - 1}")

if p_value < 0.05:
    print("→ Reject H₀: The die does not appear fair")
else:
    print("→ Fail to reject H₀: No strong evidence the die is unfair")
```

### How the Chi-Square Statistic Works

The chi-square statistic is computed as:

$$\chi^2 = \sum \frac{(\text{Observed} - \text{Expected})^2}{\text{Expected}}$$

Each category contributes a term. Categories where observed and expected are close contribute little to the statistic. Categories with large deviations contribute a lot. The statistic is always non-negative, and larger values indicate worse fit.


```
# Manual calculation
contributions = (observed - expected) ** 2 / expected
print("Contributions by face:")
for i, (obs, exp, contrib) in enumerate(zip(observed, expected, contributions)):
    print(f"  Face {i+1}: observed={obs}, expected={exp}, "          f"contribution={(obs-exp)**2}/{exp} = {contrib:.4f}")
print(f"\nTotal chi-square: {contributions.sum():.4f}")
print(f"scipy chi-square: {chi2_stat:.4f}")
```

## Chi-Square Test of Independence

The test of independence asks whether two categorical variables are related. This is one of the most widely used tests in data science because it answers questions like:

* Does the marketing channel affect which product customers buy?
* Is customer satisfaction related to the support agent they spoke with?
* Does the country of origin influence which payment method users choose?

### Setting Up the Contingency Table

The starting point is a contingency table (also called a cross-tabulation), which shows the frequency of each combination of categories.


```
# Scenario: Does marketing channel affect product purchase?
np.random.seed(42)
n = 500

# Simulate data where channel DOES affect product choice
channel = np.random.choice(["Email", "Social", "Search"], size=n, p=[0.3, 0.4, 0.3])
product = []
for ch in channel:
    if ch == "Email":
        product.append(np.random.choice(["Basic", "Pro", "Enterprise"],                                         p=[0.3, 0.4, 0.3]))
    elif ch == "Social":
        product.append(np.random.choice(["Basic", "Pro", "Enterprise"],                                         p=[0.5, 0.35, 0.15]))
    else:
        product.append(np.random.choice(["Basic", "Pro", "Enterprise"],                                         p=[0.2, 0.3, 0.5]))

df = pd.DataFrame({"channel": channel, "product": product})

# Create contingency table
contingency = pd.crosstab(df["channel"], df["product"])
print("Contingency Table:")
print(contingency)
print(f"\nTotal observations: {contingency.values.sum()}")
```

The expected frequencies show what the contingency table would look like if the two variables were completely independent. The chi-square statistic measures how far the observed counts deviate from these expected counts.

### Understanding Expected Counts

Under independence, the expected count for each cell is:

$$\text{Expected} = \frac{\text{row total} \times \text{column total}}{\text{grand total}}$$


```
# Manual expected count calculation
row_totals = contingency.sum(axis=1)
col_totals = contingency.sum(axis=0)
grand_total = contingency.values.sum()

print("Row totals:", dict(row_totals))
print("Column totals:", dict(col_totals))
print(f"Grand total: {grand_total}")

# Expected count for (Email, Basic)
exp_email_basic = row_totals["Email"] * col_totals["Basic"] / grand_total
print(f"\nExpected (Email, Basic) = {row_totals['Email']} × {col_totals['Basic']} "      f"/ {grand_total} = {exp_email_basic:.1f}")
```

### Assumptions and Rules of Thumb

The chi-square test requires that expected counts are not too small. A common rule of thumb is that all expected counts should be at least 5. If some cells have very small expected counts, consider:

* Combining categories to increase counts
* Using Fisher's exact test (for 2×2 tables)
* Using simulation-based tests


```
# Check expected counts
min_expected = expected.min()
print(f"Minimum expected count: {min_expected:.1f}")
if min_expected < 5:
    print("WARNING: Some expected counts are below 5. Consider combining categories.")
else:
    print("All expected counts are ≥ 5. Chi-square approximation is reliable.")
```

### Effect Size for Categorical Data: Cramér's V

Just as Cohen's d measures effect size for continuous data, Cramér's V measures the strength of association between two categorical variables. It ranges from 0 (no association) to 1 (perfect association).


```
def cramers_v(contingency_table):
    """Compute Cramér's V from a contingency table."""
    chi2 = stats.chi2_contingency(contingency_table)[0]
    n = contingency_table.values.sum()
    min_dim = min(contingency_table.shape) - 1
    return np.sqrt(chi2 / (n * min_dim))

v = cramers_v(contingency)
print(f"Cramér's V: {v:.4f}")

# Interpretation guidelines
if v < 0.1:
    strength = "negligible"
elif v < 0.3:
    strength = "small"
elif v < 0.5:
    strength = "medium"
else:
    strength = "large"

print(f"Association strength: {strength}")
```

    Cramér's V: 0.2400
    Association strength: small
    

Cramér's V is independent of sample size, unlike the chi-square statistic itself. This makes it a much better measure of effect size. A highly significant chi-square test (tiny p-value) might correspond to a small Cramér's V if the sample size is large, meaning the association is statistically detectable but practically weak.


```
# Demonstrating: significance without meaningful effect size
np.random.seed(42)
n_large = 50000

# Very slight deviation from independence
channel_large = np.random.choice(["A", "B"], size=n_large, p=[0.5, 0.5])
outcome_large = []
for ch in channel_large:
    if ch == "A":
        outcome_large.append(np.random.choice(["Yes", "No"], p=[0.301, 0.699]))
    else:
        outcome_large.append(np.random.choice(["Yes", "No"], p=[0.299, 0.701]))

ct_large = pd.crosstab(    pd.Series(channel_large, name="Channel"),    pd.Series(outcome_large, name="Outcome"))
chi2_large, p_large, _, _ = stats.chi2_contingency(ct_large)
v_large = cramers_v(ct_large)

print(f"Large sample (n={n_large:,}):")
print(f"  Chi-square: {chi2_large:.4f}")
print(f"  p-value: {p_large:.4f}")
print(f"  Cramér's V: {v_large:.6f}")
print(f"\nStatistically significant? {'Yes' if p_large < 0.05 else 'No'}")
print(f"Practically meaningful? Almost certainly not (V ≈ 0)")
```

    Large sample (n=50,000):
      Chi-square: 0.8559
      p-value: 0.3549
      Cramér's V: 0.004137
    
    Statistically significant? No
    Practically meaningful? Almost certainly not (V ≈ 0)
    

## Power Analysis

Now we shift to a topic that transforms hypothesis testing from a reactive tool into a proactive one. Power analysis helps you design your experiment before you collect data, ensuring you have enough observations to detect effects that matter.

### What Is Statistical Power?

Power is the probability of correctly rejecting $H_0$ when $H_1$ is true, that is, the probability of detecting a real effect. Power = $1 - \beta$, where $\beta$ is the Type II error rate.

Four quantities are linked in power analysis. If you know any three, you can solve for the fourth:

* **Effect size:** How large is the effect you want to detect?
* **Sample size:** How many observations will you collect?
* **Significance level ($\alpha$):** What false positive rate will you tolerate?
* **Power ($1 - \beta$):** What probability of detecting the effect do you need?


```
from statsmodels.stats.power import TTestIndPower, TTestPower, GofChisquarePower
power_analysis = TTestIndPower()
```

### Computing Required Sample Size

The most common use of power analysis: "How many observations do I need?"


```
# Scenario: We want to detect a medium effect (d=0.5) with 80% power
# Two-sample t-test, α = 0.05
effect_size = 0.5
alpha = 0.05
power = 0.80

required_n = power_analysis.solve_power(
    effect_size=effect_size,
    alpha=alpha,
    power=power,
    ratio=1.0,  # equal group sizes
    alternative="two-sided")

print(f"To detect Cohen's d = {effect_size}:")
print(f"  Required n per group: {int(np.ceil(required_n))}")
print(f"  Total participants: {2 * int(np.ceil(required_n))}")
```

### Power for Chi-Square Tests

Power analysis for chi-square tests uses a different effect size measure called w, which is related to Cramér's V.


```

        alpha=0.05,
```

### Minimum Detectable Effect

Sometimes you know your sample size (it is fixed by budget or data availability) and want to know the smallest effect you can reliably detect. This is the minimum detectable effect (MDE).


```
# Given: we can collect 200 observations per group
fixed_n = 200

mde = power_analysis.solve_power(
    nobs1=fixed_n, alpha=0.05, power=0.80,
    ratio=1.0, alternative="two-sided")

print(f"With n = {fixed_n} per group:")
print(f"  Minimum detectable effect (Cohen's d): {mde:.3f}")
print(f"  This means we can detect effects of d ≥ {mde:.2f} with 80% power")
print(f"  Smaller effects would likely be missed")
```

## A/B Testing: Putting It All Together

A/B testing is where hypothesis testing, effect size, and power analysis converge in a high-stakes practical setting. It is the standard method for making data-driven product decisions at tech companies.

### The A/B Testing Mindset

An A/B test is a randomized controlled experiment. You split users into two groups: the control (A) sees the existing version, and the treatment (B) sees the new version. By randomizing, you eliminate confounders and can attribute any observed difference to the change you made.

But running a valid A/B test requires planning. You need to decide:

* What metric are you measuring? (primary metric)
* How large an effect do you care about? (MDE)
* How many users do you need? (power analysis)
* How long should the test run? (traffic $\times$ duration)
* What confidence level will you use? ($\alpha$)

### A/B Test Sample Size Calculator


```
def ab_test_sample_size(baseline_rate, mde_relative, alpha=0.05, power=0.80):
    """
    Calculate required sample size per group for an A/B test on proportions.

    Parameters
    ----------
    baseline_rate : float
        Current conversion rate (e.g., 0.05 for 5%).
    mde_relative : float
        Minimum relative lift to detect (e.g., 0.10 for 10% relative improvement).
    alpha : float
        Significance level.
    power : float
        Desired power.

    Returns
    -------
    int : required sample size per group
    """
    p1 = baseline_rate
    p2 = baseline_rate * (1 + mde_relative)

    # Effect size (Cohen's h for proportions)
    h = 2 * (np.arcsin(np.sqrt(p2)) - np.arcsin(np.sqrt(p1)))

    from statsmodels.stats.power import NormalIndPower
    analysis = NormalIndPower()
    n = analysis.solve_power(effect_size=h, alpha=alpha, power=power,                              ratio=1.0, alternative="two-sided")
    return int(np.ceil(n))

# Example: 5% baseline conversion rate, detect 10% relative lift
baseline = 0.05
relative_lift = 0.10

n_per_group = ab_test_sample_size(baseline, relative_lift)
print(f"Baseline conversion rate: {baseline:.1%}")
print(f"Minimum detectable lift: {relative_lift:.0%} relative ({baseline * relative_lift:.2%} absolute)")
print(f"Required sample size per group: {n_per_group:,}")
print(f"Total required: {2 * n_per_group:,}")
```

    Baseline conversion rate: 5.0%
    Minimum detectable lift: 10% relative (0.50% absolute)
    Required sample size per group: 31,218
    Total required: 62,436

```
print(f"p-value: {p_value:.4f}")

# Confidence interval for the difference
from statsmodels.stats.proportion import confint_proportions_2indep

ci = confint_proportions_2indep(
    treatment_conversions.sum(), n_treatment,
    control_conversions.sum(), n_control,
    method="wald")
print(f"95% CI for difference: [{ci[0]:.4f}, {ci[1]:.4f}]")

# Decision
alpha = 0.05
print(f"\nDecision (α = {alpha}):")
if p_value < alpha:
    print(f"  SIGNIFICANT (p = {p_value:.4f})")
    print(f"  The treatment shows a statistically significant improvement.")
else:
    print(f"  NOT SIGNIFICANT (p = {p_value:.4f})")
    print(f"  Cannot conclude the treatment is different from control.")
```

### Practical Considerations for A/B Testing

Here are the realities that textbooks often skip:

* **Run duration matters.** If your test runs for just a few hours, you capture only certain types of users. Run for at least one full week to capture day-of-week effects, and ideally two or more weeks for important decisions.
* **Peeking inflates false positives.** If you check results every day and stop the test as soon as you see significance, you are running a multiple testing problem in disguise. Either commit to a fixed sample size or use sequential testing methods designed for continuous monitoring.
* **Novelty and primacy effects.** Users may react differently to a new feature simply because it is new. Initial excitement fades. Run your test long enough for the novelty to wear off.


```
# Simulating the peeking problem
np.random.seed(42)
n_simulations = 1000
max_per_group = 5000
peek_points = list(range(100, max_per_group + 1, 100))

# No true effect (both groups have the same rate)
false_positive_count = 0

for sim in range(n_simulations):
    control = np.random.binomial(1, 0.05, size=max_per_group)
    treatment = np.random.binomial(1, 0.05, size=max_per_group)

    for n in peek_points:
        counts = np.array([treatment[:n].sum(), control[:n].sum()])
        nobs = np.array([n, n])
        _, p = proportions_ztest(counts, nobs)
        if p < 0.05:
            false_positive_count += 1
            break

print(f"False positive rate with peeking: {false_positive_count / n_simulations:.1%}")
print(f"Nominal false positive rate: 5.0%")
print(f"Peeking inflated the false positive rate by {false_positive_count / n_simulations / 0.05:.1f}x")
```

    False positive rate with peeking: 32.4%
    Nominal false positive rate: 5.0%
    Peeking inflated the false positive rate by 6.5x
    

The false positive rate with peeking is dramatically higher than the nominal 5%. This is one of the most common mistakes in industry A/B testing.

### The Power-Precision-Cost Triangle

Every experiment involves trade-offs between three competing goals:

* **Power:** The ability to detect real effects
* **Precision:** Narrow confidence intervals
* **Cost:** Time, money, and opportunity cost of running the experiment

You cannot maximize all three simultaneously. Increasing power requires more data (higher cost) or accepting lower precision. The art of experimental design is finding the right balance for your specific situation.

## Chi-Square and A/B Testing Combined

In many A/B tests, the outcome is not a simple conversion rate but a categorical variable with multiple outcomes. Chi-square tests handle this naturally.


```
# A/B test with multiple outcomes
np.random.seed(42)

# Control group: user actions
control_actions = np.random.choice(
    ["Purchased", "Added to Cart", "Browsed", "Bounced"],
    size=3000, p=[0.05, 0.12, 0.43, 0.40])

# Treatment group: different action distribution
treatment_actions = np.random.choice(
    ["Purchased", "Added to Cart", "Browsed", "Bounced"],
    size=3000, p=[0.07, 0.15, 0.45, 0.33])

# Combine into contingency table
all_actions = np.concatenate([control_actions, treatment_actions])
all_groups = np.concatenate([["Control"] * 3000, ["Treatment"] * 3000])

ct = pd.crosstab(    pd.Series(all_groups, name="Group"),    pd.Series(all_actions, name="Action"))
print("Contingency Table:")
print(ct)

# Chi-square test
chi2, p, dof, expected = stats.chi2_contingency(ct)
v = cramers_v(ct)

print(f"\nChi-square: {chi2:.2f}")
print(f"p-value: {p:.6f}")
print(f"Cramér's V: {v:.4f}")

# Proportions by group
print("\nProportions:")
print((ct.div(ct.sum(axis=1), axis=0) * 100).round(1))
```

## Reporting Results for Stakeholders

Technical rigor is important, but communicating results clearly is equally critical. Here is a template for reporting A/B test results to non-technical stakeholders.

```
    """Generate a formatted A/B test report."""
    control_rate = control_data.mean()
    treatment_rate = treatment_data.mean()
    lift = (treatment_rate - control_rate) / control_rate if control_rate > 0 else 0

    counts = np.array([treatment_data.sum(), control_data.sum()])
    nobs = np.array([len(treatment_data), len(control_data)])
    z_stat, p_value = proportions_ztest(counts, nobs)

    significant = p_value < alpha

    print("=" * 55)
    print(f"  A/B Test Report: {metric_name.title()}")
    print("=" * 55)
    print(f"\n  Control:    {control_rate:.2%} (n = {len(control_data):,})")
    print(f"  Treatment:  {treatment_rate:.2%} (n = {len(treatment_data):,})")
    print(f"  Lift:       {lift:+.1%} relative")
```

## Summary

This lesson has extended your hypothesis testing toolkit to categorical data and introduced the crucial concept of power analysis:

* **Chi-square goodness-of-fit tests whether observed frequencies match expected frequencies.** It compares what you see to what a specific distribution model predicts.
* **Chi-square test of independence verifies categorical relationships.** It structures data inside contingency tables and compares them to expected counts under the assumption of complete independence.
* **Cramér's V measures effect size for categorical associations.** Ranging from 0 (completely independent) to 1 (perfect association), it is independent of sample size constraints and must be reported alongside p-values to clarify practical weight.
* **Statistical power represents the probability of detecting a real effect.** It forms a tight structural link between effect size, sample size, and significance level ($\alpha$). Low-powered tests introduce extensive resource waste by missing real effects.
* **Power analysis should happen before data collection.** It calculates the required sample size needed to detect an effect of a given size with a specified confidence probability.
* **A/B testing applies these rules to digital product decisions.** Continuous peeking at accumulating figures distorts true significance parameters; design your sample size targets and run-time distributions in advance.
