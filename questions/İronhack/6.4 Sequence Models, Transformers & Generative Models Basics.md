## Recurrent Neural Networks: The Original Idea

A recurrent neural network processes sequences one element at a time, maintaining a hidden state that summarises everything seen so far. At step $t$:

$$h_t = \tanh(W_{xh} \cdot x_t + W_{hh} \cdot h_{t-1} + b_h)$$

$$y_t = W_{hy} \cdot h_t + b_y$$

In words: the new hidden state $h_t$ is a function of the current input $x_t$ and the previous hidden state $h_{t-1}$. The same weights $W_{xh}, W_{hh}$ are reused at every step, just like a convolution reuses its filter across positions.

```
       h0 ─► [RNN] ─► h1 ─► [RNN] ─► h2 ─► [RNN] ─► h3 ─► y
               ▲              ▲              ▲
               │              │              │
               x1             x2             x3

```

The three `[RNN]` boxes are the same cell with the same weights — just shown unrolled across the three time steps. Each cell takes the previous hidden state from the left and the current input from below, and produces the next hidden state.

This is called unrolling the RNN through time. To train, you compute the loss at the end of the sequence (or at every step, depending on the task), then backpropagate through the unrolled network — a process known as **Backpropagation Through Time (BPTT)**.

In PyTorch:


```
import torch.nn as nn

rnn = nn.RNN(input_size=10, hidden_size=32, batch_first=True)
out, h = rnn(x)   # x: (batch, seq_len, 10)
```

Conceptually elegant. Practically, it has a serious problem.

### The Vanishing & Exploding Gradient Problem

When you backprop through a long sequence, the gradients have to traverse many time steps. Each step multiplies by some factor related to the weight matrix and the activation derivative. If those factors are mostly less than 1, gradients shrink exponentially as you go back: that's vanishing gradients. If mostly greater than 1, they explode.

The practical consequence is brutal: a basic RNN cannot learn dependencies that span more than ~10 time steps. By the time the gradient travels back from "the cat sat on the mat" to "the", it's effectively zero. The network can't learn that "the" should agree with "cat" if there are too many words in between.

Exploding gradients are easier to fix — `torch.nn.utils.clip_grad_norm_` puts a hard cap on the gradient norm and you're done. Vanishing gradients required a real architectural change. That change was the LSTM.

## LSTMs: Gates That Let Information Flow

A Long Short-Term Memory (LSTM) cell is a fancier RNN cell that maintains two streams: a hidden state $h_t$ and a separate cell state $c_t$ that acts like a conveyor belt of memory. Three learned gates control what gets read, written, and forgotten:

* **Forget gate** $f_t$ — what fraction of the cell state to keep
* **Input gate** $i_t$ — what fraction of the new candidate content to write
* **Output gate** $o_t$ — what fraction of the cell state to expose as the hidden state

The update equations look intimidating but the structure is clean (where $\odot$ means element-wise multiplication):

$$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f)$$

$$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i)$$

$$\tilde{c}_t = \tanh(W_c \cdot [h_{t-1}, x_t] + b_c)$$

$$c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t$$

$$o_t = \sigma(W_o \cdot [h_{t-1}, x_t] + b_o)$$

$$h_t = o_t \odot \tanh(c_t)$$

The crucial line is $c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t$. The cell state is updated additively (not multiplicatively), which means gradients flow through it without vanishing. That's the whole trick. LSTMs can learn dependencies across hundreds of time steps where vanilla RNNs collapse.

In PyTorch:


```
lstm = nn.LSTM(input_size=10, hidden_size=64, num_layers=2, batch_first=True)
out, (h, c) = lstm(x)
```

### GRUs: A Simpler Alternative

The Gated Recurrent Unit (GRU) is a streamlined LSTM with only two gates (update and reset) and no separate cell state. Fewer parameters, slightly faster, often comparable performance. A reasonable rule of thumb: try GRU first; switch to LSTM if it underperforms.


```
gru = nn.GRU(input_size=10, hidden_size=64, batch_first=True)
out, h = gru(x)
```

## Sequence-to-Sequence: The Encoder-Decoder Pattern

For tasks like machine translation, you have an input sequence and need to produce an output sequence of (often) different length. The classic recipe was sequence-to-sequence (seq2seq):

1. An **encoder RNN** reads the input sequence one token at a time and produces a final hidden state — a fixed-size vector summarising the whole input.
2. A **decoder RNN** starts from that vector and generates the output sequence one token at a time.

```
   Input  (English)        "hello"   "how"   "are"   "you"
                       │
                       ▼
                ┌─────────────┐
                │   Encoder   │
                └──────┬──────┘
                       │
                       ▼
                       h       ← single context vector — a fixed-size
                       │         summary of the whole input sequence
                       ▼
                ┌─────────────┐
                │   Decoder   │
                └──────┬──────┘
                       │
                       ▼
       "salam"    "necəsən"    Output  (Azerbaijani)

```

It worked, sort of. The fundamental flaw: forcing the encoder to compress an arbitrarily long input into a single fixed-size vector $h$. For long sentences, information at the start of the input gets washed out by the time the decoder needs it.

### Attention: Looking Back at the Whole Input

The fix, introduced in 2014–2015 and refined for years afterwards, is called attention. Instead of relying on a single summary vector, the decoder gets to look at all of the encoder's hidden states and decide, at each output step, which input positions to focus on.

The mechanics:

1. For each decoder step, compute a score between the decoder's current state and every encoder hidden state.
2. Pass these scores through softmax to get attention weights — a probability distribution over input positions.
3. Compute a weighted sum of the encoder hidden states using these weights — that's the context vector.
4. Use this context vector to produce the next output token.

This means the decoder can attend to "salam" coming from "hello" while attending to "necəsən" from "how are you". Translation alignment becomes learnable, not implicit. Attention turned out to be such a powerful idea that it eventually replaced recurrence entirely.

## Self-Attention: The Key Insight

The next big leap was realising that you don't need encoders and decoders to compute attention — and you don't need recurrence at all. Self-attention lets every position in a sequence attend to every other position in the same sequence directly.

For each position $i$, you produce three vectors from the input:

* **Query** $q_i$ — what this position is looking for
* **Key** $k_i$ — what this position offers
* **Value** $v_i$ — the content this position contributes

Each of these comes from a learned linear projection of the input embedding. To produce the output at position $i$:

1. Compute scores: $\text{score}(i, j) = q_i \cdot k_j$ for every other position $j$
2. Scale by $\sqrt{d_k}$ (where $d_k$ is the key dimension) to keep gradients stable
3. Softmax across $j$ to get attention weights $\alpha_{ij}$
4. Output is $\sum_{j} \alpha_{ij} \cdot v_j$

In matrix form (for the whole sequence at once):

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) \cdot V$$

This is scaled dot-product attention, the heart of every modern language model.

### Why Self-Attention Beats Recurrence

* **Parallelism** — RNNs process sequences one step at a time. Self-attention computes all positions in parallel, which makes training on modern GPUs enormously faster.
* **Long-range dependencies** — every position can directly attend to every other position with constant path length, instead of having to propagate information through many recurrent steps.
* **Interpretability** — attention weights are inspectable; you can literally see which words the model is paying attention to.

The cost: self-attention is $O(n^2)$ in sequence length. For very long sequences this becomes a real constraint, and a lot of recent research is about reducing this cost. But for sequences up to a few thousand tokens, it's not a bottleneck.

### Multi-Head Attention

Rather than computing one attention pattern, modern transformers compute several in parallel — each with its own learned $W_Q, W_K, W_V$. Different "heads" learn to attend to different things: one head might track syntactic relationships, another semantic ones, another long-range coreference. The outputs of all heads are concatenated and projected back to the model dimension.

In PyTorch:


```
attn = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
out, weights = attn(query, key, value)
```

## The Transformer Architecture

Put scaled dot-product self-attention in a clean architectural envelope and you get the Transformer — introduced in *Attention Is All You Need* (Vaswani et al., 2017). The original transformer has an encoder and a decoder; modern variants often use only one or the other.

A single transformer block looks like:

```
Input Embedding
       │
       ▼
   Multi-Head Self-Attention
       │
   Add & LayerNorm  ◄── (residual connection)
       │
       ▼
   Feedforward (Linear → ReLU → Linear)
       │
   Add & LayerNorm  ◄── (residual connection)
       │
       ▼
Output

```

The residual connections (just like in ResNet) and Layer Normalisation are crucial — without them, transformers don't train at deep depths. You stack these blocks to build the network. GPT-style models stack many decoder blocks; BERT-style models stack many encoder blocks; the original transformer used both.

### Positional Encoding

There's a subtle issue with self-attention: it has no built-in notion of order. The attention output depends only on which tokens are present, not on their position. If you shuffle the input sequence, the output is shuffled too — but the relationships are preserved.

That's wrong for language: "dog bites man" and "man bites dog" should give different outputs. The fix is positional encoding — add a vector to each token embedding that encodes its position. The original transformer used fixed sinusoidal encodings:

$$\text{PE}(pos, 2i) = \sin\left(\frac{pos}{10000^{2i/d}}\right)$$

$$\text{PE}(pos, 2i+1) = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$

Modern variants often use learned positional embeddings (just another lookup table) or RoPE (Rotary Position Embeddings), which encode positions multiplicatively. The exact choice matters for very long sequences but for the conceptual model, "we add positional information to the embeddings" captures the essential idea.

### Encoder vs Decoder vs Encoder-Decoder

Three families of transformer models, each suited to different tasks:

| Family | Examples | Best for |
| --- | --- | --- |
| **Encoder-only** | BERT, RoBERTa | Understanding text — classification, NER, similarity |
| **Decoder-only** | GPT, Llama | Generation — language modelling, chat, code |
| **Encoder-Decoder** | T5, original Transformer | Sequence-to-sequence — translation, summarisation |

Decoder-only models like GPT use causal (masked) self-attention: each position can only attend to positions before it. That's what allows autoregressive generation, where each token is predicted given only what came before.

You'll meet these models more deeply in Unit 8 (LLMs). For today, knowing they're all built from the same self-attention building block is enough.

### When to Use What in 2026

* **Vanilla RNN** — basically never. Historical interest only.
* **LSTM / GRU** — small datasets, short sequences, very low-latency requirements where a transformer is overkill. Still found in some forecasting and audio pipelines.
* **Transformer (encoder-only)** — text classification, named entity recognition, sentence similarity, anything that needs deep understanding of a fixed-length input.
* **Transformer (decoder-only)** — generation: text, code, anything autoregressive.
* **Transformer (encoder-decoder)** — translation, summarisation, structured input-to-output transformations.

For most problems involving sequences, "use a transformer" is the right starting answer in 2026. The interesting question is which pretrained transformer to start from — but that's tomorrow's lesson on transfer learning.

### Beyond NLP: Transformers Everywhere

Worth flagging: transformers are no longer just for text.

* **Vision Transformers (ViT)** treat an image as a sequence of patches and feed it to a transformer encoder. They now compete with — and in many benchmarks beat — CNNs.
* **Audio transformers** model speech and music as sequences.
* **Time-series transformers** are increasingly used for forecasting alongside LSTMs.

The same self-attention mechanism, repurposed for different data types. Knowing how attention works pays off across many domains.

## Generative Models — A Quick Tour

We've spent the whole unit so far on discriminative models: given an input $x$, predict a label or value $y$. Classifiers, regressors, CNN feature extractors — they all answer "what is this?"

There's an entirely different family of models that answers "produce something new that looks like this". Those are generative models, and they're the reason your phone can edit photos with a text prompt, why ChatGPT can write essays, and why Stable Diffusion can paint anything you describe. We won't dive deep into them in this unit — the field deserves its own unit, and you'll see them used in Unit 8 (LLMs). But you should at least know the four big families and what each one is good at.

### Autoencoders

The simplest generative architecture. An encoder compresses $x$ into a small latent vector $z$; a decoder reconstructs $x$ from $z$ alone. Trained with a reconstruction loss like MSE.

```
       x
       │
       ▼
   ┌─────────┐
   │ Encoder │
   └────┬────┘
        │
        ▼
        z          ← compressed latent code
        │
        ▼
   ┌─────────┐
   │ Decoder │
   └────┬────┘
        │
        ▼
        x̂          ← reconstruction

```

Autoencoders are great for representation learning, denoising, and anomaly detection (high reconstruction error = unusual input). They're surprisingly bad at generating new samples, though: feed a random vector to the decoder and you typically get garbage, because the decoder only knows how to reconstruct latent codes from the training data.

### Variational Autoencoders (VAEs)

A VAE fixes the "garbage from random latents" problem by forcing the latent space to look like a standard Normal distribution. The encoder outputs a mean and variance, you sample $z$ from that distribution, and the decoder reconstructs from $z$. The loss has two terms — reconstruction error + a small "stay close to $N(0, I)$" penalty.

After training, you can sample any $z \sim \mathcal{N}(0, I)$, feed it through the decoder, and get a new, plausible-looking sample. VAEs are easy to train and give you a structured latent space you can interpolate in — at the cost of slightly blurry samples.

### Generative Adversarial Networks (GANs)

A GAN pits two networks against each other:

1. A **Generator** takes random noise and produces fake samples.
2. A **Discriminator** tries to tell real samples (from the dataset) apart from fakes.

```
   z (noise)
       │
       ▼
   ┌───────┐
   │   G   │
   └───┬───┘
       │
       ▼
    fake x        real x
       │            │
       ▼            ▼
   ┌─────────────────┐
   │  Discriminator  │
   └────────┬────────┘
            │
            ▼
   "real" or "fake"

```

The two networks play a minimax game: the generator gets better at fooling the discriminator, the discriminator gets better at spotting fakes, and at equilibrium the generator's samples are indistinguishable from real data.

GANs produce remarkably sharp, realistic samples — when they converge. They're also famously finicky to train, with failure modes like mode collapse (generator only produces a few outputs) and oscillation. StyleGAN for human faces and CycleGAN for image-to-image translation are still strong tools in their niches.

### Diffusion Models

The current state of the art. A diffusion model is trained to reverse a slow noising process:

* **Forward process** — take a real image and add Gaussian noise step by step until it's pure noise.
* **Reverse process** — train a network to remove one step of noise at a time, so we can walk back from pure noise to a clean sample.

At inference, you start from random noise and iteratively denoise it for many steps. The output is a brand-new sample that looks like training data. Stable Diffusion and DALL·E are diffusion models conditioned on text prompts; Midjourney, MusicGen, and most modern video generators are diffusion-based too. Diffusion gives you stable training (the loss is just MSE on noise prediction), top sample quality, and easy text conditioning. The main downsides are slow sampling (many denoising steps) and large models.

### Where Generative Models Show Up

It helps to organise the four families by "what they're known for":

| Family | Strengths | Weaknesses | Famous uses |
| --- | --- | --- | --- |
| **Autoencoder** | Simple, learns compressed representations | Bad at sampling new data | Anomaly detection, denoising, representation learning |
| **VAE** | Structured latent space, easy to train | Blurry samples | Representation learning, controllable generation |
| **GAN** | Sharp, realistic samples | Hard to train, mode collapse | Face/image generation (StyleGAN), domain translation (CycleGAN) |
| **Diffusion** | Stable training, top quality, easy conditioning | Slow sampling, large models | Text-to-image (Stable Diffusion, DALL·E), audio, video |

In your day-to-day work in 2026 you'll mostly use pretrained generative models rather than train them from scratch — diffusion models in particular take industrial-scale compute. But knowing the architectures helps you read papers, pick the right tool, and reason about what's possible.

## Summary

You've travelled the entire history of sequence modelling in one lesson, and finished with a brief tour of the generative-model zoo:

* RNNs introduced the idea of a hidden state but couldn't learn long-range dependencies because of vanishing gradients.
* LSTMs and GRUs added gating mechanisms and additive cell-state updates that let information (and gradients) flow over long sequences.
* Sequence-to-sequence with attention broke the fixed-vector bottleneck of plain encoder-decoder RNNs by letting the decoder look back at all input positions.
* Self-attention removed recurrence entirely, making sequence modelling parallel and direct, and it became the foundation of the Transformer architecture.
* Multi-head attention, residual connections, layer normalisation, and positional encoding are the architectural ingredients that make transformers work.
* In 2026, transformers — encoder-only, decoder-only, or encoder-decoder — are the default for sequence tasks across text, vision, audio, and beyond.
* The four big generative families — autoencoders, VAEs, GANs, and diffusion models — let you produce new data rather than just classify it. Diffusion is the current state of the art for images, audio, and increasingly video.

In today's lab you'll build both an LSTM and a small transformer on the same toy task (next-character prediction on a small text corpus) and watch how dramatically faster and more accurate the transformer is.
